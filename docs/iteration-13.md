## 局部校正与精确账本

旧实现每次校正均重建全部 position，丢失未修改证券的 lot 日期、费用依据，并把内部派生单位成本重新送进六位小数输入校验。当前默认 `patch`：按本次明确字段修改，原样回传按 Decimal 数值比较；未改成本直接沿用精确 total_cost，不经单位成本舍入重建。

| 输入 | 语义 |
| --- | --- |
| 缺省字段 / UI 留空 | 保持原事实 |
| `cost_price: null` / 明确成本未知 | 清除成本依据，不自动补零 |
| `available_quantity: null` / 明确可卖未知 | 清除可卖依据 |
| `available_quantity: '0'` | 明确本次上海日期当天零可卖，区别于未知；原有等值可卖依据及未来解锁日保持 |
| 从非零改为 `quantity: '0'` | 明确清仓，不虚构卖出或已实现盈亏 |
| `remove: true` / 移除证券行 | 明确移除持仓范围，包括原已为零的行；不删除历史账本 |
| 单改数量 | 保留精确剩余总成本；新增量可卖未知，减少量的剩余可卖依据需重新明确，预览说明 |
| 单改成本 | 保留原批次 / 可卖日期；新成本输入仍受精度、范围和有限数校验 |
| 仅改现金或证券 A | 所有未改证券的完整事实保持 |

界面先请求后端差异预览，再带 `preview_token`、输入版本确认；输入、版本、生效日期变化时必须重新核对。同值格式不会制造校正，新 corrections API 完全无变化返回明确错误，不新增版本或研究；旧 PUT 同值保存仍沿用兼容保存流程。旧 PUT 只有明确提供 holdings 时才使用完整列表；缺省现金、持仓及单行成本保留原事实，显式 null 与缺省参与不同幂等指纹。另有 6 项旧入口缺省清除失败真实复现与回归，见账本操作说明。完整模式和兼容入口的细则见 [账本操作说明](thirteenth/ledger-corrections.md)。日常页面提交稀疏改动。CAS、operation_id、回执核对、账户隔离与原子研究需求提交沿用生产路径。
