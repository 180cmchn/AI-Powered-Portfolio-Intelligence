# 第七轮预测评估口径

本功能记录账户研究团队的正式方向预测，不模拟交易，也不把模型置信度、建议动作或交易收益当准确率。短线、中线、长线分别是默认 1、5、20 个交易日的产品标签；修改期限后显示实际天数，已发布记录仍按原规则计算。

## 固定批次与探索记录

旧账户升级后默认关闭新正式批次，启用会增加每日模型研究费用。启用账户在交易日 15:30 后锁定固定批次范围，默认 18:00 截止；当日至少一项指定证券的精确收盘数据可取得后才派发模型研究。全部基准日线暂缺时，预期样本仍显示“待数据”，截止后明确记为因缺基准漏预测，不从覆盖率中消失。范围固定为该账户持仓与候选证券的并集，所有证券乘所有期限都建立预期样本，分页不会删除未覆盖项。规则、账户输入版本、基准日和截止时间在批次中保存；同账户同日修改设置不能另造第二批正式样本。完全离线而未观察到当日生成窗口时，不伪造当时的证券范围或补造预测。

manager 发布账户报告时，在同一数据库事务中提交 `forecasts`：证券、期限、`up / sideways / down / abstain`、理由与引用。证券和期限须属于服务端冻结的范围，发布时间、基准和规则由服务端绑定。只有当前、未取消且成功发布的报告能写入账本，首次正式结果锁定；重复提交不更改方向。未提交项留为未覆盖，截止后标为漏预测；弃权与失败单列。

普通研究在运行前冻结探索批次，盘中采用最近已经收盘的交易日作为基准，清楚记录实际锁定及发布时间。这些记录与固定正式批次分开，修改观点也不能取代原正式样本。如果研究跨过了该期限的目标收盘才发布，保留原记录并标为“发布晚于目标收盘、不可评估”，不会把已经可知的结果算作前瞻命中。没有事前规则的历史报告不会被回填为预测。

## 到期与行情证据

基准交易日 D 不计入期限，目标日为 D 后第 N 个交易日。交易日历仅在明确覆盖区间内计算；年末缺覆盖时，只把相关期限列为待数据。`STOCK_CALENDAR_PATH` 可指向现有单个日历文件，也可指向包含 `calendar_*.json` 的目录，用交易所已发布并核实的年度文件扩展。每份文件都要声明 `coverage`、`source` 和 `holidays`（或完整 `trading_dates`），临时变更放入 `overrides`。不猜测下一年的工作日。后续补齐日历时，目标日解析另存证据，原预测记录不改写。

评估读取证券的精确基准日和目标日日线，不取当前报价或最近可用一日。保存两端原始行、数据来源、取得时间、数据版本和计算口径。停牌、零成交、缺日、无效价格或不支持的可比口径显示待数据或不可评估，不当作零收益、不顺延目标日。

价格规则 `same_source_pair_v1` 在发布前固定：先取得同源未复权两端收盘价，再取得同一次返回的后复权两端。两套价格的比例一致时使用原始收盘比；不一致时统一使用这次后复权两端，记录调整依据，避免分红、拆分和份额折算造成机械误判。无法取得同源调整证据时保留缺口。现有 Tushare 适配器只提供未复权股票日线，因此该口径下会明确等待可比调整数据；不会偷偷用未经确认的原始跌幅评分。

默认阈值为 `0.005`（0.5%），按未经展示舍入的精确比值计算：

- 收益率大于 +0.5%：上涨。
- 收益率小于 −0.5%：下跌。
- 两个边界及其间：震荡。

各期限使用相同的总区间，不随天数缩放。准确率为命中数除以已评估数，未到期、弃权、失败、漏预测、待数据和不可评估不进入该分母。覆盖率为已提交方向或明确弃权数除以全部预期样本，同时另给方向覆盖率。没有成熟样本时准确率为 `null`，页面应显示“暂无已评估样本”。不同期限和规则版本分别展示；累计准确率按总命中除以总评估计算。

## 可靠性与历史修订

评估不调用模型，也不依赖供应商 Key、角色配置或新研究启停；暂停评分也不会停止已经启用的新批次。服务恢复后按到期队列读取对应历史日线补算；午休的 `closed` 状态不会触发当日收盘评估。每轮默认最多 30 项评估，其中历史复核最多 6 项，优先保留首次评分名额；有效评分默认 7 天复核，不可评估默认 14 天复核，数据等待采用退避。详情的“请求重新检查行情更正”可单独登记即时复核。持久短租约防止手动和自动评分同时抓取同一预测，进程中断后租约到期可恢复。同版本重复评估不重复累计；真实更正另存修订，包括数据恢复成旧值的情况。临时网络失败作为价格观察保留，不把已有有效评分移出分母。

正式账本保存原报告内容、实际团队及角色绑定、原引用与发布时信息上界，即使之后修改模型、持仓或角色，也不重新署名。账户间比较只计算相同基准日、证券、期限和规则的共同样本，展示未重合数量；即使维度相同，材料清单和额外搜索仍可能不同，不能据此宣称严格对照模型优劣。

`tests/test_sixth_forecasts.py` 使用明确的历史行情和时钟夹具验证这些规则。夹具不是已经积累的真实 5/20 日前瞻表现；真实准确率必须从启用后的实际事前记录到期后形成。

## 第七轮身份与分母

任务领取时、解析凭据之前记录每次执行的账户、批次、任务、角色、供应商连接修订、请求模型、effort 和团队/提示词版本。计划配置、观察到的请求、报告发布分开表达，前置失败不会冒充实际调用。未发布样本归最近一次已冻结的尝试；新重试仅入队时保留旧归属，领取新配置后才切换。已发布预测始终归实际发布团队，不随 Key 轮换或目录刷新改署。

A 失败后 B 重试成功：正式预期样本仍只有原来 3 条，发布后属于 B；A 的失败保留在独立执行尝试统计中。筛选 A 时可看到 1 次失败尝试，但不重复复制 3 条正式样本。失败、等待配置、未覆盖样本仍能按当时已确定模型/团队筛选。没有可靠历史证据的样本使用“配置未确定/历史归属未知”，不读取当前配置补造归属。

评分规则身份从保存的完整规则计算，包含期限、阈值、价格口径、交易日定义和窗口时间，去除显示标签、账号和随机批次标识；`0.005` 与 `0.0050` 为同一口径。原 `rule_version` 保留，`forecast_rule_projections` 提供规范映射。批次 ID 独立唯一，同账户同日可有多个探索批次；正式日唯一约束保持。详情同时展示原版本和规范规则。

探索统计保留所有发布次数，不覆盖相反方向的先后两次研究。当前未预先锁定跨账户探索时间窗口，因此探索比较明确“不可直接配对”，所有未配对数量可见，不取最后一次或事后胜者。正式比较仍按交易日、证券、期限、规则一对一，显示实际发布时间、资料与搜索可能不同。

## 每日窗口运行与轻量调度

每日窗口表单位是“账户 × 计划日期”，记录实际发现时间、当时配置依据、状态及范围是否已知。整窗离线后可标记错过、历史未知或日历未知；可信历史范围只作缺口说明，不生成预测或加入已建立批次的样本分母。账户尚未创建、明确暂停、非交易日分别记录。窗口内配置变化保留修订；范围发生变化而无法给出唯一预期范围时显示未知。

当日批次先入库，基准准备和评估并行。每个正式方向样本发布前必须有该证券同一精确 D 日的有效基准；缺失项保持待数据，报告可发布，不代为改成弃权。发布后的基准不被迟到数据重写。单周期相同证券/来源/日期/口径行情合并，保存不可变证据，下一周期仍可观察真实更正。

设置 API 支持 `forecast_evaluation_batch_size=30`、`forecast_review_batch_size=6`、`forecast_evaluation_concurrency=4`、`forecast_request_timeout_seconds=20`、`forecast_cycle_timeout_seconds=45`、`forecast_review_interval_days=7`、`forecast_unassessable_review_days=14`、`forecast_baseline_batch_size=40`。列表在数据库中分页，聚合仅使用当前评估修订；批次列表不携带完整提示词和请求正文，按需打开详情。
