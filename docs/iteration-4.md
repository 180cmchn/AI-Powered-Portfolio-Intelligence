本轮基于 `2468b2505fb05d2ce3bdbf1bc30ed55a5c803905` 实施，初始工作区干净。未回退第三轮修复，未修改用户 `.env`、删除密钥、清空业务库或推送远程。评估只读取项目配置；所有运行写入独立评估库。

## 实现与根因

- 原先把所有工具统一包装为 function，无法执行服务端联网。现在 Responses 同时提供原生 `web_search` 和本地 functions；主/子 Agent 都能自主搜索。原生调用绝不派发本地，真实输出与引用完整保留，原生工具中间结果会继续而不被误当最终报告。
- 原先设置依赖独立搜索平台和旧数据库 `disabled`。schema4 将 `model_native_search` 独立迁移，默认沿用模型凭据；明确关闭会保留。旧值留在数据库审计，退出运行路径。能力状态包含关闭、未验证、观察到执行、不支持、认证失败、请求失败；探测有界且十分钟缓存，刷新不花费模型调用。
- 原先长历史和工具事件重复进入主 Agent 汇总，单次请求仍约90秒。新增请求阶段/规模/耗时/状态/请求ID/用量诊断，减少传给主 Agent 的重复明细，`prepare_synthesis` 压缩为可见成果。研究请求90秒、汇总120秒、整轮600秒分别限制；不使用未经验证的流式响应。原始超时的远端内部原因无法仅靠客户端证据确定。首轮实际运行耗尽18轮而未提交报告，现明确提示剩余预算，最后一轮仅保留报告提交能力，不增加总预算或伪造最终结果。
- 可见检查点保存子报告、材料索引、计算和未决问题。恢复前验证账户/范围版本、全部相关报价、资料版本/权限/时效和新事件；不合格重新研究。每检查点最多两次恢复、每次最多四次模型请求，成功发布同事务消耗检查点。子报告和半输出不算最终完成。
- 原先文档版本按入库顺序推进。现在应用采集层在HTTP前持久分配可信观测序号；缓存/重启保留顺序。迟到旧观测可引用但不提升、更正不通知；真实新观测 A→B→A 仍识别。无法排序的原文变更保存顺序未知，不捏造发布者更正。
- 原先提取身份只纳入 `material_ids`，别名 `source_material_ids` 会丢来源。现在两字段取排序去重并集并参与身份；跨账户/未知父引用保留缺口，不泄露资料，历史已丢来源不补造。
- 原生来源分别保存链接或实际片段，与本地下载原文和生成提取分开。链接没有原始字节哈希、全文或页码。可见引用映射至有权限的已存来源；位置0→0不伪称已定位。
- 资讯观察进入原有公共研究队列。关联计划随公共报告同事务保存，之后幂等投递账户/建议；中断后不重新调用模型。未知关联扩大复核，生成报告不回流为外部新闻。首轮真实运行发现自己采集的来源在失败后会立即触发下一轮；现将来源事件持久绑定当前公共研究，失败保留待处理状态，等待明确重试或新事件，不按每个 tick 重新执行。
- 行情保留东方财富适配，增加有限重试、限流停止、身份/格式校验和真实时间缓存。休市可使用同供应商未复权最近日线收盘价，源时间仅日期时明确标注，不触发盘中新鲜行情条件。新增可关闭的新浪公开网页报价备用源，验证身份与源时间，不绕过429；全通道断连仍显示不可用，不能用搜索价格补数。
