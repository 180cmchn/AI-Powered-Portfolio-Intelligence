# 第十轮界面与任务交互验收

本文件记录生产 FastAPI + 临时 SQLite + Chromium 的工程交互验收。证券目录、模型结果和凭据库是显式受控替身，不能用这些浏览器结果证明真实模型研究质量、正式预测覆盖或收益准确率。日常数据库和服务未用于写入测试。

## 用户路径和修复对应

| 现场反馈 | 原因 | 实现与验收 |
| --- | --- | --- |
| 点击后不清楚是否启动 | 已有短 toast，但没有持久任务关联 | 提交期间显示操作 ID；后端返回后显示真实 queued / running / waiting_config 等状态、账户、冻结输入版本、任务 ID；结果入口指向确切报告。丢响应按操作 ID 只读核对，不自动重新付费 |
| 任务对象、入口与结果归属不清楚 | reason 文案承担多种含义；来源及冻结范围缺少显示 | 使用服务端 task_kind / trigger_source / origin / target；创建、计划、执行开始、结束分开；重试父任务、合入需求、计划交易日保留。历史未知明确未知 |
| 长小窗无法直接关闭 | 对话框整体滚动 | 标题、正文、底部操作区分开；仅正文滚动，约束包含块高度以适配缩放。原生 dialog 保留 Esc 与关闭后的焦点恢复，并显式约束首末可见控件的 Tab 循环 |
| 六位代码保存 422 | 输入层只允许已规范标识 | 前端允许纯六位文本；失焦调用统一解析端点显示代码、名称、市场及缓存时点；多匹配显示可选项。后端整批校验，错误保留草稿；观察、候选与持仓独立 |

`app/static/app.js` 同时分离材料的来源类型、访问范围和陈述分类。新增 `unclassified` 显示“尚未分类”；历史 `uncertain` 保留含义不确定，不批量改写成事实或传闻；只有明确 `rumor` 显示传闻。仅链接条目的操作为“查看检索元数据”，不再声称存在本地正文。

## 可重复的浏览器场景

运行 `PYTHON=.venv/bin/python node tests/run_browser.mjs`。四组既有回归分别是 iteration、production、seventh、ninth；新增 tenth 独立报告。所有需要 HTTP 的组使用临时回环端口；tenth 使用生产路由和临时 SQLite，未启动模型 worker。

新增组覆盖：

- 100 条引用默认收起，计数准确；后台新增材料触发真实轮询重绘，展开状态与滚动不变。
- 1280×800、1024×680、390×740，以及 Chromium CSS zoom=1.25 / 2 的布局缩放场景。长报告正文的顶部、中部、底部都检查关闭按钮的矩形边界与实际命中目标，并检查关闭按钮、Esc、焦点恢复和键盘焦点限制。CSS 布局缩放是可执行替代场景，不宣称操纵了浏览器原生缩放菜单；用户原始截图未附在工作区，1024×680 不是对截图精确尺寸的声称。
- 持仓帮助文字多行换行时，三列输入顶部/高度与删除按钮按元素坐标断言；小屏证券字段单独一行，数量/成本保有可用宽度。
- 用户三行 518880 / 688825 / 562500、159278、000001、规范代码混合去重；保存后真实监控非空。部分非法批次整批不保存，原稿切账户后仍保留。
- 双击提交、实际 queued / running / waiting_config、合入原任务、响应丢失、首次核对也失败后刷新恢复、切账户隔离、失败重试父链；F 失败后重试并入已排队 Q 时保留 Q 身份，同时来源条目仍可打开 F。
- 持仓裸代码保存时响应丢失，通过账户写 receipt 确认原版本与原任务，仅一次 PUT；数量修改为 20,000 后现金仍为 10,000。
- 恢复汇总当前没有新调度专题时，仍显示原任务遗留缺口；原专题总数未知，不将当前 0/0 声称为研究无缺口。
- 无持仓/候选的现金账户在启动前明确确认仅现金与偏好；自选不自动成为持仓/候选。

## 验收过程发现

最初新增组发现：仅使用 `90vh` / `100dvh` 在 CSS zoom=1.25 时仍能让关闭按钮越出可见区域。已改为同时约束包含块百分比，随后几何断言通过。

首次五组执行后，人工查看截图发现前端仍将 API 合同硬编码为 9，而后端已升为 10。原有测试检查了交互，但未断言兼容提示，因此不能据首次通过就宣布新版完整验收。此项以及历史分页顶部任务、弹窗内增量事件、跨账户 toast 清理、合入需求显示均已修复并按明确断言通过。键盘新增断言还发现原生 Shift+Tab 边界可使焦点进入 body，现已显式循环首末可见控件。最终验收结果和截图见 `browser-validation.json`，不再使用含兼容警告的早期截图。

## 最终工程结果

四组既有回归及新增组均通过，JavaScript 异常 0。最后一次五组整体运行耗时分别为 iteration 2.000 秒、production 8.978 秒、seventh 4.595 秒、ninth 16.628 秒、tenth 18.747 秒。此整体运行包含单证券探索范围发布修复、任务恢复后端、入口动作/需求状态本地化、合并重试的来源父链，以及恢复成果中原专题缺口的单独显示、真实导航取消竞态和纯文本材料 ID 的只读引用解析。准确启动源码/静态资源摘要、实例、API/schema 版本保存在 `browser-validation.json`。

## 使用方法

1. 在持仓“证券代码”或市场的自选/候选框输入六位代码；可换行或使用中英文逗号、分号。确认自动识别的名称和市场后保存。
2. 点击“立即分析”或行情行“研究此证券”；上方持续显示真实任务状态。排队仅表示已接受，没有虚构百分比或完成时间。
3. 打开任务卡的“查看账户报告”或“查看证券报告”。报告正文优先；“任务结果与调用统计”和恢复检查点仅作为诊断。
4. 点击“引用定位（N 条）”展开来源及访问范围。仅链接资料打开检索元数据，外部来源链接另行打开。
5. 失败时查看实际阶段与原因，点击“重试当前版本/重试最新版本”；原任务和父链保留。若提示提交/保存结果未确认，先点只读核对，不重复发起研究。
6. 系统设置中的“当前服务启动版本”显示启动时提交、源码摘要和 API/schema；修改源码不会让日常进程自动变成新版。升级与备份步骤以本轮主交付和 Mac 手册为准。

## 真实实例只读复核

`ui-live-task.json` 与 `ui-live-task*.png` 来自已运行的独立真实模型实例。观察时虚拟 A 输入 v2、159278 20,000 份、现金 10,000 元；任务处于 running / researching，尚无最终报告。浏览器全部 API 请求限于 GET/HEAD，未触发研究、重试或配置写入。Agent 工作台内的任务弹窗可关闭，JS 异常 0。

这次真实观察发现从账户总览状态条直接打开任务会被隐式 hash 切页取消自己的读取；先进入 Agent 工作台可打开。该失败没有隐藏，已保存 `ui-navigation-regression-before.json`，并用生产临时库的延迟 GET 场景复现。真实任务结束后已移除隐式切页；overview / market / holdings 三个入口的延迟 GET、弹窗 ID、原页不跳转与焦点恢复全部通过，五组回归再次通过。

A 随后实际完成并发布原始报告 `bd6211d06f79431bbd378dc6f9524b1f`。修复后用 SQLite `mode=ro` 读取评估库并一致性备份到临时副本，再启动 `worker=False` 的生产 FastAPI；服务器和浏览器均拒绝非 GET/HEAD 请求。已确认从账户总览和市场页状态条直接打开原任务、关闭，以及打开未改写的原报告。`ui-live-task-fixed.json`、`ui-live-task-fixed-overview.png`、`ui-live-task-fixed-market.png`、`ui-live-task-fixed-report.png` 保留这次实证；临时库已删除，原评估库未写入。原运行截图和导航失败证据仍保留，与修复后证据分开。此只读查看不代表额外模型研究或预测准确率验收。

最后一次只读查看还展开了原报告的引用定位，并实际打开两处已解析材料：日线结构化内容保存 8,826 字符（本次首段读取 6,000 字符），基金季报选页 1–4 共 3,226 字符。原模型正文的 SHA-256 仍为 `4d10dcd471af40e58d41e9c54dc30b42f196eb3f604cc1f80022b6edf2252a70`。原评估库和临时副本在查看前后，持久化报告、任务结果及全部 164 条阅读记录的签名均相同；用户查看材料没有伪造模型阅读记录。
