# 第六轮：需求覆盖、恢复、调度与账户隔离验证

本记录使用临时 SQLite 数据库、受控时钟、明确标识的历史价格夹具以及 HTTP 协议替身。没有把这些结果当作真实供应商可用性或真实前瞻准确率。日常数据库与 macOS 钥匙串没有用于这里的测试；`tests/conftest.py` 在导入 `app.main` 前设置独立 `APP_DB_PATH`。

## 研究需求按实际覆盖完成

`Service.execute()` 不再从账户最近 100 条需求中筛选任务。`task_demands()` 按任务冻结需求 ID 集合，初始提供 25 条，`list_business_demands` 可按页继续读取。返回总量、下一页位置和冻结范围；运行中新增的账户需求不会挤掉本轮旧事项。

主 Agent 在 `finish_analysis.covered_demand_ids` 中明确列出处理过的整数 ID。发布事务只完成属于当前任务、已向运行时提供且明确提交的需求。其余保留为 `uncovered`，报告结果保存完整覆盖计数与逐项状态。明确维持、修订或撤销建议的原有复核完成语义继续有效。

`uncovered` 不自动触发无限模型调用。手动重试会重新安排这些事项及失败事项，已完成事项保持完成。重复发布不会改写首次覆盖记录。任务曾包含的需求即使移交下一任务，冻结范围也不会因此缩小。

生产链复现位于 `tests/test_sixth_repairs.py`：同一任务 150 条需求，研究期间另到 120 条。通过真实 `Service.execute → ResearchTools → Store.publish` 分页取得原 150 条，仅明确完成 100 条，50 条保持未覆盖；并验证重复发布、重启后手动重试和其他任务 ID 不越权完成。另测只看第一页却声称处理未读页时，未曝光 ID 不会被完成。

## 检查点记录观察版本，而非保存时最新版本

检查点材料保护信息现在分别保存：引用材料自身的文档版本 ID、版本号、片段哈希、片段范围、表示类型、父来源 ID，以及保存时最新可用的文档版本。生成提取结果的原始父链一并检查。数据库出现 v2 不会把 Agent 所读的 v1 改记为 v2。

恢复时比对当前材料及流头，且不接受已知落后的原文作为“仅汇总即可恢复”。任务开始时的事件保护值与保存时最新事件保护值分别记录。旧检查点使用有缺陷的版本证明格式，不能追溯证明观察范围，因此不作新格式的仅汇总恢复依据；原历史内容仍保留。

验证覆盖 v2 在检查点之前和之后到达、迟到旧观测、内容真实回滚、同一原文不同片段、原始父链变更、未变化材料成功复用、恢复次数上限和账户隔离。没有用全面禁用恢复来绕过问题。

完整团队快照仍保存在检查点与结果中。恢复结果保留各旧子报告的角色、实例和原 `model_config`，同时标明当前汇总配置。发送给模型的检查点只投影团队 ID、版本与各角色绑定；长提示词、工具定义和凭据引用不重复塞入模型上下文，避免恢复标志和研究内容被无必要的大快照淹没。旧子报告不会改署为当前团队生成。

## 行情、预测评估与模型研究分别调度

`scheduled_research_enabled` 控制自动创建研究及正式预测批次；`market_refresh_enabled` 控制自动行情刷新；`forecast_evaluation_enabled` 控制已有预测的到期评分。行情和评分分支在模型研究开关检查前执行，模型配置缺失不应阻断这两类维护。

休眠恢复和启动时过期缓存检查也遵守相应开关，避免关闭定时研究后因重启隐蔽产生研究费用。显式暂停三个分支后，待办和已有账本继续保留。

`tests/test_sixth_service.py` 使用生产调度器与真实预测存储路径验证：午休不把当日当作已收盘；收盘后按指定日期评分；睡过目标交易日后周末醒来补评历史收盘，而不重新生成预测；跨年日历缺覆盖只影响相应样本；关闭模型研究仍刷新行情、仍评分；休眠与重启尊重开关；显式全暂停不调用维护分支。

## 共享原始资料，不共享生成结论

账户研究上下文不再注入全局 `shared_research`。账户查询 `research_records` 只返回本账户的生成记录；公共研究历史仍可由用户查看。公共材料索引只把原始资料表示作为跨账户输入。

材料检索、全文读取、搜索片段、引用解析和父来源解析使用一致的账户边界。模型保存的内容强制归类为 `agent_extraction`，不能通过提交 `scope=public` 或伪造原文类型变成公共原始资料。历史 `material_uses` 不是新的访问授权，不能据此再次向另一账户暴露结论。原始网页、公告、实际搜索片段和行情仍可跨账户复用。

公共来源事件路由只携带需要调查的原始材料 ID。它不把公共主 Agent 的投资结论或解释作为账户研究证据。测试同时验证账户自己的提取内容可读、原始来源可共享、其他账户及公共模型生成结论不可检索、引用父链不可越权取回。

## 多模型运行时结构验证

`tests/test_sixth_runtime.py` 先通过真实供应商保存/目录发现方法读取受控 HTTP 列表，再设置统一角色默认及账户覆盖。两个账户都拥有完整六角色目录，通过正常 `Service.tick()` 领取任务，随后执行真实 `ResearchRuntime` 和 `ModelClient` 请求序列化。

捕获到的请求验证了 Responses 与 Chat Completions 的独立来源、凭据、原始 `model_id` 和 effort。同名模型仍以供应商 ID 区分；带斜杠的 ID 原样发送。每账户同一研究角色有三个独立实例，其中一个继续原会话追问。运行过程中修改 A 的角色绑定、修改全局提示词并轮换 Key：原实例、追问，以及本轮稍后才创建的实例仍使用原冻结配置；新任务才采用新配置，B 的账户覆盖不变。

子模型故意调用 `finish_analysis` 会被工具权限拒绝，不能写正式预测或账户最终报告。缺少 `role_id`、未知角色、递归派发 manager 以及在派发参数中覆盖模型或 effort 均被拒绝。请求审计包含账户、角色、实例、供应商修订和模型；结果与事件不记录明文 Key。原生联网来源记录现在使用实际调用实例的配置指纹，不能把子供应商观测记在 manager 名下。

本分支局部回归实际运行结果：121 项通过，覆盖上述 2 项运行时测试、8 项缺陷/隔离测试，以及第四、第五轮恢复、材料、需求、建议与事件路由相关回归。部分旧测试夹具更新为显式需求覆盖、目录发现后的角色绑定及第六版迁移；原先“账户复用公共模型结论”的断言按本轮明确产品要求改为隔离。完整项目回归、浏览器和真实外部执行结果见第六轮总交付记录。
