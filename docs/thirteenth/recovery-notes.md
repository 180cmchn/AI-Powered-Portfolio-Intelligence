# 第十三轮研究恢复与收尾交付

本轮修改保留既有首有效事件、语义空闲、请求硬限、子任务和整轮预算，不切换协议、模型或 effort，也不自动重发已接受而结果未知的请求。此文的回归全部使用生产 Service / Runtime / Store / HTTPX 客户端与临时 SQLite，模型 HTTP 由受控 transport 提供；真实供应商结果必须另看本轮 live 记录。

- 00:30:20.661，第二个子报告完成，晚于汇总开始约 14.224 秒。完成并保存不能证明已进入先前的请求。
- ETF 子请求与主汇总后来均发生响应体不完整。既有 39 次请求、37 次完整终止、2 次失败、0 账户报告、0 正式预测的分母保留。约距末字节 50 秒断流并不等于触发 120 秒语义空闲或 300/360 秒请求硬限；客户端证据不能定位唯一供应商/转发器/代理组件。
- 最终检查点保留 2 个子报告、50 个完成计算、2 条报告交付回执，仍有一个未完成专题。4 个资料范围的原因是 `visible_report_source_not_received`，因此既有仅汇总资格被拒绝。这个判定不意味着已完成的计算和所有原始资料都不存在。

本轮只补记响应的 `http_version`，原有 exception cause 类型链、请求 ID、传输阶段、代理环境是否存在、terminal、末字节与末有效进展继续保留。代理地址、凭据和原始流不进入新增诊断。旧记录没有 HTTP 版本，不能回填推断。

## 显式重试复用有效成果

原来 `reusable_synthesis_checkpoint()` 只接受 `synthesis_ready`，其余有效检查点全部舍弃，新任务重新研究。本轮保留原来的仅汇总分支，并为当前账户明确指定原任务的重试增加 `continue_research`：

1. 仍核对账户 / 输入版本、公共范围版本、行情及事件范围、材料版本和访问权限、检查点时效与恢复次数。没有通过这些 guard 的旧研究不自动变成当前结论。
2. 只有显式 `parent_job_id` 对应的检查点可进入继续研究模式，普通 worker / scheduler 不因此新增任务或自动付费重试。
3. 在新的干净模型会话中真实交付已完成子报告、计算摘要、来源索引与未解决范围。已中断响应的半截正文、函数参数和 opaque continuation 不会导入。
4. 继续研究保留主 Agent 的原有工具和角色选择权；是否补查、重读已存原文、派发专题或交付有限分析由主 Agent 在共享预算内判断。仅汇总模式继续禁止扩展搜索和创建子任务。
5. 报告交付仍保留原 task / agent / round / model / material receipt。主 Agent 收到子报告不冒充亲读原文。继续研究再失败时，新检查点保留原报告来源和本次已经完成的材料读取回执。
6. `research_recovered` 表示复用了成果，`synthesis_recovered` 只表示仅汇总恢复；`recovery_mode` 明确二者。界面提示继续研究可能产生模型和联网费用，且不承诺仅汇总可用。

时效或输入变化后，本轮仍保守转入当前输入的新研究；已保存原始材料继续可通过已有材料工具检索，但不会默认将旧投资结论重新标成有效。没有扩展旧检查点 TTL、修改原失败或预测评分。

## 收尾等待与实际纳入

固定 30 秒不是子模型的完成承诺。本轮在进入最终收尾时停止扩展研究，等待范围改为：现有子任务剩余截止时间，与整轮剩余时间扣除最终请求保留时间的较小值。无整轮 deadline 的内部调用仍保留 30 秒上限；生产 `run()` 总有 deadline。子任务完成即可提前返回，预算耗尽则保留缺口，不无限等待，也不增加整体时限。

新增 `budget_closeout` / `budget_closeout_finished` 字段记录进入原因、剩余时间与调用、在途实例、已完成报告和未完成实例。最终输入在等待结束之后构造。新增每个主请求的 `research_context_delivery`，在最终压缩及预算检查之后、HTTP 尝试之前记录实际请求中出现的报告 ID、原任务以及 `full_report` / `report_summary` 范围；报告交付不等于模型采用。原计算可见范围事件继续记录摘要、索引、省略情况。请求发出后晚到的报告仍由既有有界最终更新逻辑处理，不能自动标为已使用。

## 工程回归

[新增测试](../../tests/test_thirteenth_recovery.py) 覆盖：

- 真实生产 Service→Runtime→SQLite 链中的研究断流、有效但不足以仅汇总的检查点、明确重试、带入完成报告、读取已有原文后完成有限报告。
- 再次断流后继续重试，原任务仍 failed，新报告和原材料回执保持来源，没有重放半截函数。
- 没有明确父任务不进入继续研究，行情 guard 变化拒绝复用，读取诊断不消耗恢复次数。
- 收尾等待在 100 秒剩余 / 36 秒最终保留的受控条件下可给已有子任务约 64 秒，而不是固定 30 秒；任务实际立即完成，无真实 64 秒 sleep；完成报告进入生产最终上下文。
- 无剩余预算立即保留未完成子任务，不等待、不声称完成。
- 受控 HTTP/1.1 断流记录请求 ID / cause 类型 / 代理存在性，接受后不重发、不执行未终止函数、不输出代理秘密，费用未知不计零。

相关既有恢复、超时、协作、计算与收尾回归一并运行，最新结果见 [测试日志](recovery-tests.txt)。这些受控测试不能替代真实供应商报告验收；本轮真实验证由独立实例、固定源码及统一总调用闸单独记录。
