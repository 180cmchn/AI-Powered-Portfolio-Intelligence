# 第十一轮：虚拟成交、费用与资金账本

本轮将日常持仓维护改为用户手动录入虚拟已成交买卖。没有券商订单、撮合、模型下单或自动执行建议。下面的金额均为受控测试输入，不是日常 `test` 账户的真实交易或市场报价。

## 实现与事务边界

- `app/ledger.py`：确定性费用、现金、移动加权平均成本、可卖批次、资金调整、校正、末笔撤销和费用更正。
- `app/store.py`：schema 11 迁移与在线一致性备份、账户快照/版本/研究队列事务、旧账户 PUT 的账本约束。
- `app/ledger_api.py`：HTTP 输入校验、六位代码生产目录解析、预览和提交；行情仅为参考，提交不依赖行情 HTTP。
- `app/domain.py`：估值使用账本精确总成本，不从已显示/取整的单位成本反推；累计费用不再次从权益扣减。
- `tests/test_eleventh_ledger.py` 和 `tests/test_eleventh_api.py`：生产 Store/API 的独立数据库回归。

每笔提交使用 SQLite `BEGIN IMMEDIATE` 串行处理。账户版本和费用方案版本必须与预览时一致；现金未知、现金不足、超卖、数量/价格错误或可卖依据不足会在任何写入前拒绝。同一个本地事务写入：不可变业务记录、不可变资金记录、当前持仓/总成本、现金、账户输入版本、旧报告失效、输入快照、持久研究需求、去抖队列和操作回执。外部模型在事务提交后执行；研究失败不撤销已记账业务。

每笔 `operation_id` 与规范化 payload 的哈希绑定，相同内容返回原回执，不增加费用、份额或研究任务；复用 ID 提交不同内容产生冲突。账户后来更新也不改变原回执。响应未知时应查询 `ledger-operations/{operation_id}`，不生成新 ID 重发。多标签页并发读取相同账户版本时，最多一笔通过 CAS；后一笔必须重新核对余额和版本。

## 数据与会计口径

流水页面与API当前展示最近200条业务和资金记录；汇总费用/已实现盈亏仍聚合全账。当前没有历史流水分页，不把最近列表称为全部历史。

新表 `ledger_accounts` 标记期初来源；`fee_plans` 保存逐版本费用协议；`ledger_positions` 是可重建的当前持仓投影；`ledger_entries` 是不可变买卖/资金/校正/冲正记录；`cash_entries` 是对应现金变化；`ledger_operations` 是持久幂等回执。历史业务、现金、方案和回执四表由 SQLite triggers 禁止 UPDATE/DELETE。当前持仓投影允许在同一事务内替换。

金额、数量、价格、比率均从字符串进入 `Decimal`，核心成本计算在 50 位精度的局部上下文执行。数量必须为整数股/份。成交价格按股票 0.01 元、已支持 ETF 0.001 元的最小变动单位检查。成交金额先保存 `gross_raw = price × quantity`，现金入账金额按分四舍五入并保存 `gross_rounding`；费用各分项分别四舍五入到分。费用记录同时保存原始计算、实际扣款、估算、方案版本、完整方案和覆盖理由。

买入总成本增加成交金额及可资本化买入费用。卖出按精确剩余总成本与份额比例结转，净收入减结转成本为已实现盈亏。完全卖出时剩余成本归零。`cost_price` 是兼容旧显示的单位成本；会计事实以 `total_cost` 为准。有正份额的旧成本未知时始终保持 `null`，后续加仓不会将未知期初变为零成本；零份额没有未知存量成本，随后新买入建立自己的已知成本；完整盈亏显示“成本依据不足”，趋势研究仍可执行。之后补成本只影响有依据的当前校正，不改写历史已实现盈亏。

初始现金与转入/转出均标 `external_flow`，不算投资收益。字段 `cash` 只表示模拟可用现金，不表示券商可提现金额，也没有实施完整清算/交收。

## 税费与实际协议

默认方案是“常见模拟模板（待用户确认佣金协议）”：股票/ETF 分别佣金万三、最低 5 元，股票过户费万分之 0.1（0.001%）另列，股票卖方印花税 0.05%，ETF不收这两项股票税费。经手费/监管费默认作为佣金包含项展示，不另扣；管理费/托管费不在场内每笔成交扣年费。该模板不是用户券商合同。

方案支持沪/深市场覆盖、stock/etf 区分、买卖方向覆盖、最低佣金、佣金包含过户费、明确生效日期和确认状态。费率字段是比例：`0.0003 = 万三 = 0.03%`；`0.0005 = 万五 = 千分之0.5 = 0.05%`；`0.00001 = 万分之0.1 = 0.001%`。一条记账记录是一笔收费单元，不支持将同一订单的多个小成交分别聚合最低佣金。

实际券商佣金和最低费用在持仓管理的费用方案中填写。已包含过户费的佣金方案不会重复扣过户费；版本变更只影响新交易。单笔实际费用可以在提交时用有依据的 `fees_override` 覆盖，原估算保留；仅填写理由、没有任何费用数值的覆盖会拒绝，不能把估算伪标为实际费用。仅核实过户费/印花税而佣金仍来自未确认模板时，整笔仍标估算；`actual_override_components` 保存确实提供实际金额的分项，后续费用更正继承该证据。若入账后获得交割单，可对**末笔交易**提交独立 `fee_adjustment`：引用原单、保留原费与新费及差额；买入更正调整剩余成本和现金，卖出更正调整已实现盈亏和现金，不新收一次交易费。更早交易涉及后续成本回放，当前明确拒绝；不伪造反向交易。

来源和核对证据见 [现行税费与交易规则来源](iteration-11-fee-sources.md)。每个方案附来源 URL、公开发布日期/生效日（未披露即 null）、适用说明和核对日期 2026-10-30。没有将券商公开标准称为用户专属协议。

## 交易规则与边界

证券身份使用第十轮生产目录的精确代码/市场/品种缓存；未确认的显式手工代码不能直接记账。普通沪深主板/创业板 A 股支持买入 100 股整数倍与 T+1；科创板、北交所及其他品种明确提示当前范围未实现，不猜其交易单位。

`SH:518880` 按华安黄金ETF官方 T+0 公告支持当日可卖。`SZ:159599`、`SZ:159278` 及已有明确的境内股票ETF产品集合按 T+1；已确认目录可提供 `fund_type=domestic_equity` 扩展普通股票ETF。未确认 ETF 子类别时拒绝并解释“规则待确认”，没有从代码前缀或名称未出现特殊词就推断 T+0/T+1。ETF买入单位为100份。零股/零份卖出采用保守产品限制：不足整手的提交只支持一次卖出全部当前可卖余量；不会用多个小额提交拆分零股。

持有量、可卖量、可卖依据未知数量分别展示。新买入保存批次可卖日期，T+1 使用现有有覆盖的交易日历，不用“自然日加一”跳过假日。期初持仓没有买入日期时可卖量未知，不猜历史日期；用户可在有理由的校正中明确 `available_quantity`，自本次校正日期起作为确认的可卖余额。

`traded_at` 与不可变 `recorded_at` 分开。历史成交须是已核实交易日；休市可以记录明确标注的模拟业务。禁止未来成交；仅允许按账户现有成交时间顺序追加，不支持任意历史插单重算。实际录入时间不会回写旧输入快照、历史预测、正式截止或评分。

## 迁移、旧接口和撤销

Store 在升级前通过 SQLite online backup 保存 `.before-v11.bak`，迁移在事务中完成、可回滚、重复启动幂等。schema10原账户现金、持仓、成本、版本、报告与旧快照不改变；建立带原 `updated_at` 来源和迁移录入时间的期初基线，不按现价扣钱、不推测旧交易或买入日期。原成本存在就保留，有份额而缺失成本时保持未知。旧版允许的非整分现金（例如100000.005）也原样保留，但新买卖、转入转出与费用更正拒绝隐式取整，先要求有依据的校正到分。该校正及其撤销保留精确亚分差额，使原余额加资金变动严格等于新余额。

新建账户的现金成为明确期初资金记录。普通旧账户 PUT 不能覆盖派生现金/持仓；需明确 `ledger_action=correction`、`adjustment_reason` 与 `expected_version` 才能走同一校正服务。高级校正可在同一事务保存名称/偏好，保留前后值；日常 UI 使用独立元信息入口和买卖入口。

录错可对账户末笔非期初、非冲正业务追加 reversal，恢复对应财务前值，冲回原费用，不把它当反向买卖重新收费；若综合校正之后另有账户版本更新，则保留最新名称/偏好，不用旧校正覆盖后来元信息。更早记录不支持任意撤销/回放，会明确提示限制。有交易、资金、校正等后续记录的账户不能由旧删除接口无痕删除；只有期初的账户仍兼容删除账户操作，但其不可变期初和费率审计继续保存在数据库。

原版本/预测/来源回归中“修改快照”的夹具已改为明确期初校正；没有用测试辅助函数伪装真实买卖。真实供应商研究验证和生产浏览器结果由总交付记录独立列出；上述确定性单元/API测试不冒充真实模型成功。
