# Mac 启停、升级与恢复

本说明对应第十一轮代码（schema 11 / API contract 11）。运行时仍是一个本地 Python 进程、SQLite 与浏览器，不需要 CC Switch、OpenCode CLI、Node 或另外的 Agent 服务。[第十一轮交付](iteration-11.md)记录账务、超时、界面与真实研究证据；本操作说明不代表供应商已经实测可用。

## 首次安装

需要 Python 3.12+。打开 macOS“终端”，进入实际项目目录。以下两条命令**分行执行，末尾不加连接它们的反斜杠**：

```sh
uv sync --frozen
./start.command --mode live
```

若没有 `uv`：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/manage.py start --mode live
```

依赖同步只更新虚拟环境，不会重启已有进程，也不会重新导入已有配置。只有启动输出“当前版本已就绪”或“基本 API 与实例身份已核对”才表明通过本地就绪检查；它不证明模型或原生搜索可用。

打开 `http://127.0.0.1:8765`。Finder 双击 `start.command` 也可启动；没有虚拟环境时脚本先使用可用的 `uv` 或 Python 安装依赖。已有 `.venv` 不会在每次启动时重装。项目已有 `.env` 应保留，不要用示例覆盖。正常新增模型供应商直接在网页填写三项连接信息，不必手工维护模型名称或 Key 环境变量。

## 日常已有实例启动

再次执行 `./start.command --mode live` 是幂等操作。脚本核对实际 PID、启动实例 ID、模式、端口、数据库路径、启动时源码摘要、环境文件是否修改以及必需 API；相符才显示就绪。提示“旧实例仍运行 / 需要安全重启”时，请按下一节处理。修改代码、更新依赖或编辑 `.env` 后不能仅重复 start 就认为旧进程已更新。

```sh
.venv/bin/python scripts/manage.py status --mode live
./stop.command --mode live
```

管理脚本提供 `start`、`stop`、`status`，均接受 `--mode live|demo` 和 `--port 端口`。前台排查可在停止后台服务后执行 `.venv/bin/python scripts/serve.py`；后台日志为 `data/live.log`。只允许回环地址与单个 worker，服务先占住端口并获取同库文件锁，再构造 Store；已占用的库不会先迁移后拒绝。停止超时保留 pidfile，不强杀其他端口占用者。默认数据库是 `data/live.sqlite3`；显式设置 `APP_DB_PATH` 时使用该路径，备份/恢复前应核对实际目标。

关闭网页不会停止后台研究。Mac 睡眠时不执行任务；唤醒或重新启动后恢复持久任务并处理待数据/待评分记录。不会在第二天补造昨天未及时发布的正式预测。重启电脑后需要再次启动服务，本项目不自动安装登录项或 LaunchAgent。

演示模式使用独立库与默认端口：

```sh
./start.command --mode demo
.venv/bin/python scripts/manage.py status --mode demo
./stop.command --mode demo
```

打开 `http://127.0.0.1:8766`，演示固定样例不代表真实模型、行情或已到期预测表现。

## 修改环境连接如何生效

优先推荐在网页“模型供应商”填写 API Key、Base URL、协议三项。模型名称始终来自该供应商的真实目录，在 Agent 配置中选择。

兼容环境变量为 `MODEL_BASE_URL`、`MODEL_PROTOCOL`、`MODEL_API_KEY`（或 `MODEL_KEY_ENV` 指定的变量）、历史 `MODEL_NAME` 和 `REASONING_EFFORT`。读取的是项目根目录 `.env`；已有 shell 环境优先，保持 python-dotenv 默认不覆盖行为。诊断只展示来源、是否存在与冲突，不输出 Key。不要在聊天中上传完整 `.env` 或 HAR。

- 全新库只有 URL/Key/协议：识别连接，不随机挑选第一个模型。打开供应商页面会有界获取目录；随后到全局 Agent 角色选择主 Agent 及所需子角色模型。未选择时显示“供应商已识别，主 Agent 待绑定模型”。
- 旧库迁移时没有 Key，后来补写 `.env`：先按安全步骤备份并重启，再打开“模型供应商 → 环境连接检测”，核对目标 URL/协议与来源，选择“确认目标并导入环境连接”。这一操作幂等，不复制角色、不改账户覆盖。
- 网页配置与环境连接不同：网页已保存连接和显式角色选择继续生效。环境变化仅显示待导入，不会在每次启动时无条件覆盖。更换端点/协议/凭据产生新修订，旧目录与能力缓存不能继续充当新连接已验证依据。
- 已明确清除/撤销的连接不会因读取 `.env` 复活。应在网页明确输入新凭据。历史 `MODEL_NAME` 仅为待确认绑定，目录中不存在时继续要求选择。
- 保存连接后目录失败：连接仍已保存，按失败阶段检查认证、限流、目录接口或网络，然后在原连接上“刷新模型列表”。不要反复创建。写响应丢失时页面先核对操作结果，禁止自动重发；不确定时保留提示。

配置状态分开显示本地 API、连接、Key、目录、主 Agent 绑定及函数/原生搜索能力。选中账户时采用该账户的覆盖后配置；某个子角色有误不影响供应商页和其他基础操作。能力探测是明确触发的真实请求，目录可见不等于函数或原生搜索通过。Chat Completions 的原生网页搜索本轮仍未适配。

供应商表单的 Key 仅留在当前输入 DOM；轮询和局部错误保留焦点与输入，提交成功或取消后清除，不写入通用草稿或浏览器存储。旧后端缺少写接口时输入仍可编辑，提交会禁用并说明升级步骤。离开页面会清除秘密；含 Key 时整页刷新前会提示。

## 网页模型绑定、角色和预测

1. **模型供应商**：填写 API Key、Base URL 和协议。Key 保存到 macOS 钥匙串；自动请求目录，查看成功、部分、认证失败或接口未支持等实际状态。刷新和继续加载只获取模型目录，不自动对全目录发付费推理请求。
2. **Agent 角色**：六个初始角色全局存在。逐行选择供应商、实际发现的模型和 `low / medium / high / xhigh / max`。职责、提示词、工具和全局启停在此管理；主 Agent 根据问题自主决定调用路径，不要求每轮全部角色运行。
3. **账户模型**：新账户自动继承完整目录。按需覆盖某行的模型对或 effort；清除覆盖回到默认，不删角色。配置错误仍显示该角色，不能使账户 A 的错误阻塞 B。
4. **预测评估**：选定账户并展开固定批次设置，明确开启新正式批次。默认每天 15:30 在收盘数据可用后发起、18:00 截止；期限为未来 1、5、20 个交易日，震荡阈值为 ±0.5%。页面显示启用状态与模型费用提示，旧账户升级不会自动补跑正式历史批次。

模型列表可见不代表账户有调用额度、服务接受全部 effort 或原生联网已验证。系统设置中的两个能力检测使用全局主 Agent 当前默认绑定，会产生真实请求费用，只证明实际观察到的该组合能力。Chat Completions 原生搜索不属于本轮适配范围。

## 暂停的范围

| 入口 | 设置 | 实际范围 |
| --- | --- | --- |
| 系统设置 → 定时研究 | `scheduled_research_enabled` | 控制新定时模型研究；暂停不取消手动或已持久化研究事项，不停止行情和已有预测评估。 |
| 系统设置 → 基础行情刷新 | `market_refresh_enabled` | 控制自动报价刷新；不删除已有报价和预测账本。 |
| 系统设置 → 已发布预测的评估 | `forecast_evaluation_enabled` | 控制到期历史数据评估；恢复后按原日期补算，评分不调用模型。 |
| 账户预测规则 → 正式预测批次 | `enabled` | 控制该账户以后新正式批次；不删除、改写或提前结算旧预测。 |
| `stop.command` | 整个本地服务 | 停止后台进程，持久数据与未完成事项仍保留。 |

基准日 D 不计入未来期限；新发的 5/20 日正式预测需等待真实到期，页面应显示待到期。价格缺失、停牌、日历缺覆盖或调整证据不足分别留下原因。准确率不是交易收益，也不把弃权或漏预测当作震荡。规则详情见[预测评估口径](forecast-evaluation.md)。

## 代码升级必须安全重启

旧进程加载的 Python 代码不会随磁盘更新。第九轮开始，HTML/JS 也固定为启动时资源；更新代码后需要显式重启才能生效。更早的进程可能混用磁盘新页面与旧 API，出现路由 404。不能把 404 直接诊断为断网或 Key 错误。

先执行只读诊断，核对 PID、模式、端口、数据库和源码。网页可用时使用“备份数据库”；网页不可用时使用下列 SQLite 在线备份命令。备份会包含活动 WAL 的一致视图，不迁移源库：

```sh
.venv/bin/python scripts/inspect_runtime.py --url http://127.0.0.1:8765
.venv/bin/python scripts/backup.py --mode live
```

核对备份成功输出的实际路径，并记录目标库、模式、端口、当前PID、待升级提交和备份路径。自定义库请给两个命令明确传 `--database /absolute/path/live.sqlite3`。本轮开发仅验证日常库的一致副本；不会自动升级仍在运行的日常实例。**用户确认目标与备份、且可以中断该实例的研究后**，在同一项目目录执行：

```sh
./stop.command --mode live
uv sync --frozen
./start.command --mode live
```

没有 `uv` 时使用 `.venv/bin/python -m pip install -r requirements.txt` 更新依赖。停止再启动才能加载最终代码；仍在运行的旧进程不能证明新版本正常。

schema 10 或更早数据库进入第十一轮前，程序在取得同库独占锁之后，先使用 SQLite 在线备份写入同目录 `<数据库文件名>.before-v11.bak`，然后幂等升级到 schema 11。建立期初基线、不可变成交/资金记录和费用方案，失败回滚、重复启动不重复基线。已有现金、数量、成本和未知值原样保留，不按旧持仓推造买入或追溯扣钱；旧证券可卖数量未知时需有依据的显式校正。账户、材料、报告、预测及凭据引用保留，旧 `.before-v*.bak` 不覆盖。新任务时间策略迁移规则见[超时说明](iteration-11-timeouts.md)，已运行和历史任务快照不改写。

每日运行记录从本次升级观察到的设置开始积累。升级前没有历史启用依据的日期不倒推；“错过窗口”是运行记录，不是补写预测。页面“时间运行完整性”独立于批次覆盖与方向准确率，模型未知的漏跑日期不会转嫁给当前模型。服务一直暂停时也记录暂停事实；手动检查评分不改变研究开关。

旧 Base URL、协议及环境变量安全引用提取为供应商；旧 model name 和 effort 迁移到各统一角色默认。名称保留为历史绑定并标 `legacy_unverified`，不是新目录发现证据；在页面取回真实模型目录后确认。无效历史连接或 effort 显示待修复，不默认替换成另一模型或强度。新正式批次默认关闭，已有研究节奏保留。

## 数据库备份与恢复

页面“备份数据库”调用 SQLite 在线备份，输出 `data/backups/*.sqlite3`。不要把运行中的主库文件简单复制当作包含 WAL 的一致备份。恢复时使用页面返回的真实路径：

```sh
./stop.command --mode live
.venv/bin/python scripts/restore.py data/backups/live-YYYYMMDD-HHMMSS-ffffff.sqlite3 --mode live
./start.command --mode live
```

`restore.py` 接受 schema 1–11，核对完整性、模式和数据库锁；恢复前再保存 `data/backups/before-restore-*.sqlite3`。live 与 demo 不混用。恢复较旧库后，启动时按当前代码迁移；新于程序支持版本的库会被拒绝。要回退代码到第十轮，需同时恢复 `.before-v11.bak`，不能让旧代码读取新版库；回退会失去备份之后的新记录，应先另存当前在线备份。

SQLite 备份包含业务数据、连接和安全凭据引用，**不包含钥匙串 Key，也不复制 `.env` 文件**。不要提交或公开数据库或本机 `.env`。恢复数据库也不能恢复已经明确删除的钥匙串秘密。

## 换机和凭据恢复

在新 Mac 安装项目、恢复目标模式数据库后，在“模型供应商”重新输入 Key，刷新目录并确认各角色绑定。不要把密文和解密密钥一起装进数据库或把 Key 写入浏览器 localStorage。旧环境变量兼容连接也可以通过页面输入新 Key，转换为新钥匙串修订。

Key 输入留空表示保持原值；掩码不是新 Key。轮换创建独立凭据修订，已启动任务保持旧引用；明确清除会撤销旧引用并阻止其后续 HTTP，历史预测仍可追溯。系统钥匙串不可用或未授权时，页面会显示错误，不退回明文存储；先在正常本地启动环境解决钥匙串授权再重试。详细实现与安全验证范围见[供应商与统一角色](sixth-provider-roles.md)。

## 交易日历维护

默认文件是 `data/calendar_2026.json`，当前默认覆盖到 2026 年。`STOCK_CALENDAR_PATH` 可指向一个已核实文件，或含 `calendar_*.json` 的目录；每份文件需有明确 `coverage` 和来源，采用交易所休市安排或完整交易日期，临时更正使用 `overrides`。将更新后的环境配置用于新进程后重新启动服务。

未覆盖的未来日期保持未知，不按普通工作日推算。补齐日历后新日期继续增量扫描，同时每账户每轮最多核对32个旧待解或日历修订日期。首次发现与状态变化保留修订记录；不补造旧预测。已有目标重新解析不一致时，原预测日期不改写，旧评分暂停有效性并保存纠正依据。正常行情缺失与单证券停牌不是日历缺口，不能靠延长覆盖区间掩盖。

## 只读排错与核对正在运行的版本

```sh
.venv/bin/python scripts/inspect_runtime.py --url http://127.0.0.1:8765
# 独立验证服务请显式传它的端口和数据库，不要拿日常数据库配临时端口
.venv/bin/python scripts/inspect_runtime.py --url http://127.0.0.1:YOUR_PORT --database /absolute/path/evaluation.sqlite3
```

检查脚本仅以 SQLite 只读模式读取 schema/模式/配置存在性，核对监听 PID、来源目录、GET method/path/status/content-type、OpenAPI 路由缺口和静态资源摘要；不会导入main、建立Store或执行迁移。新版页面系统设置展示进程创建时的提交、源码摘要、未提交状态和schema。旧服务没有这些字段时显示无法确认加载版本，不能以磁盘HEAD替其署名。源码有未提交修改时摘要比提交号更有区分力。

第八轮历史记录曾观察到日常 8765 为 schema 3。第九轮现场只读检查（2026-10-30，Asia/Shanghai）没有观察到 8765 监听，磁盘日常库仍为 schema 3；这不是对先前浏览器 404 根因的追认。开发未启动、停止或迁移日常实例。用户首次升级前仍须核对实际状态并备份。第八轮默认角色增加按行行情查询/指标工具及委派提示；迁移只匹配旧内置提示词和默认工具列表，已自定义的权限和提示不会被覆盖。

`app.main`现在只在ASGI启动时创建默认应用；单纯导入工厂不会创建或迁移日常数据库。测试仍应显式指定临时库，并禁用dotenv/真实模型。

### 如何解释诊断结果

| 观察 | 含义与下一步 |
| --- | --- |
| 连接拒绝 / 无监听 | 服务当前未启动或端口不对；先核对运行命令和端口。 |
| GET `/api/providers` 404 且健康或页面可达 | 本地接口缺失/版本不兼容，不能称作网络断开；安全升级重启。 |
| 对象详情 404 | 该 ID 不存在或不在当前范围；不与路由缺失混为一谈。 |
| 目录结果 401/404/429 | 上游认证、目录路径或限流问题；已保存连接仍在。 |
| 启动摘要与磁盘不同 | 旧进程未加载新源码；备份后安全重启。 |
| database_matches_requested=false | 当前端口不是指定数据库实例；不要据此迁移或停止其他服务。 |

检查不会自动重连、停服、导入环境或探测付费模型。不要删除 `.lock`、清 WAL 或使用端口全量 kill 来“修复”。

### 独立验收

`PYTHON_DOTENV_DISABLED=1 .venv/bin/pytest -q tests/test_ninth_lifecycle.py` 使用临时副本、随机独立端口、临时 SQLite；Mac 使用实际 zsh 的 `start.command` / `stop.command`，Linux 使用同一 Python 管理入口。`APP_RUNTIME_DIR` 可把实验 pidfile/log 独立放在临时目录，但正常日常使用无需设置它。测试会明确报告真实钥匙串和外部供应商是否另外验证，协议替身不等价于真实授权。

依赖同步的定义见 [uv 官方说明](https://docs.astral.sh/uv/concepts/projects/sync/)；项目锁定 python-dotenv 1.2.4，非覆盖读取行为见 [python-dotenv](https://github.com/theskumar/python-dotenv)。
