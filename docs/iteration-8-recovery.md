# 第八轮：委派研究交付与汇总恢复

本节对应 `85c530c8cb83727c87ddf6edc2df447fbbf980d9` 的恢复问题。修改集中于 `app/recovery.py`、`app/agents.py` 和主／子角色提示；使用现有 Store、ResearchTools、Service、Runtime、冻结角色配置与 SQLite，未增加审核 Agent、事实准入或内容评分。

## 根因和改动

原 `checkpoint_source_coverage` 在主 Agent 的汇总声明引用子报告的材料时，只认主 Agent 自己的原文读取收据。专家实际读取当前 v1、主 Agent 已收到专家报告，也会被当作未处理来源；错误理由又统一使用 `visible_report_has_unprocessed_correction`，即使从未发生更正。

现在保留两类独立交付：

- `research_material_deliveries` 继续记实际读取的材料版本、字符／页码／结构化行范围及接收实例。市场指标只登记返回中实际可见的输入日期和 close 字段；不会把整个材料记为已读。
- 最小新增表 `research_report_deliveries` 记主 Agent 收到的子报告：原任务、实例、角色、模型配置、研究轮次、不可变报告 ID／内容摘要、来源读取链、交付渠道、完整报告或摘要。数据库唯一键合并重复交付，不产生主 Agent 的原文阅读记录。

子报告 ID 与轮次由 Runtime 在本轮结束时生成，模型填写的报告收据或原文收据不参与授权。报告识别只接收 Runtime 的子报告渠道及已知的实际 `agent_status`／`wait_agents`／`cancel_agent` 有界输出；模型在 `save_material` 中回显一个报告 ID 或复制报告内容，不能取得报告交付资格。交付记录来自主会话实际保留的结构化可见消息；发送前，`ModelClient` 完成上下文压缩并通过凭据／预算检查后，Runtime 的现有请求钩子记录其中的报告。只完成子任务、内部执行一次 `agent_status`、材料索引、已归档而未交付的全文、截断 JSON 都不会变成完整报告交付。登记表示内容已进入本次请求的可见上下文，不声称模型理解、赞同或服务端最终成功生成报告。

`agent_status`、`wait_agents`、自动子事件、收尾上下文、晚到成果及新汇总会话都沿同一运行时记录。短摘要标记 `report_summary`；只有完整报告内容实际可见才标记 `full_report`。主 Agent 可以据合格子报告综合，无需为恢复重读所有来源；收到报告也不等于机械采用其判断。

## 恢复保护和状态

主 Agent 引用专家来源时，必须匹配该实例最新报告的 ID、内容、轮次和实际来源版本，并匹配实际读取的材料表示 ID。审查另复现了原流级覆盖判断的漏洞：读同一 v1 的片段 A，却引用未读片段 B，也曾得到覆盖；现在 B 及未读提取父材料保持缺口。实际只读 A 的三个字符仍可对该明确范围汇总，不要求全文。多个已交付专家的不同片段可以合并使用。专家已处理 v2 更正且新版报告已交付，可以综合；只有旧报告、尚未交付新版、仅引用未读 ID、仅有链接、尚在补查、真实更正未处理，均保留缺口。提取材料的父来源链仍检查实际读取范围。主 Agent 直接阅读并明确处理更正的原路径保持。

没有更正时使用 `visible_report_source_not_received` 或 `delegated_report_not_delivered`；后续补查未结束使用 `research_round_pending`。只有真实旧／新版本问题才使用更正类理由。更正中的 supersedes 只适用于已研究的历史子结论，不能消除主 Agent 自己的缺失读取、未读当前版本或尚在补查的轮次；没有旧版时更正声明不会变成交付资格。未被任何报告声明已读的原生搜索链接保留为 `index_only / source_index_not_claimed_as_read`：它是未读索引，可以与其他已完成研究一起恢复，不要求下载所有发现的 URL。子报告把未读索引列为来源时仍无法取得正文覆盖资格。

主会话断连前刚完成、尚未交付的合格子报告可保存在检查点。重试把它明确放入新的汇总会话，产生绑定新任务的交付事实；旧主会话的交付历史不补写。恢复保持原专家署名，当前主模型和原研究模型关系仍由 `configuration_relation` 表达。

账户输入、候选范围、材料 v3／回滚／父链、新事件、行情快照、检查点年龄、恢复次数、凭据检查继续保留。新增正式批次固定范围保护：正式批次 ID、日期、规则和截止改变即不可沿用；仅准备状态变化不使同批次检查点失效。探索重试按既有语义产生新运行 ID，因此比较冻结的探索日期／规则／范围，不以每次运行的随机 ID 阻断同输入恢复。历史记录不补造原交付，缺报告 ID 的历史内容不能取得新的委派覆盖资格。

检查点和最终运行结果提供 `report_access`，供页面区分“收到完整子报告（不是主 Agent 亲读原文）”与“仅收到子报告摘要”；来源覆盖理由继续单独显示，不把所有问题统称为更正。

## 研究提示调整

子角色须交付对分配问题有用的结果，或者具体说明已查内容、失败阶段、仍缺资料及其影响。主角色可在现有预算内追问更窄的问题、继续读取或明确不采用。没有关键词、最少字数、证据数量或附加审核门槛；终止工具单轮原子性保持。

提示明确：未来目标日收盘仅用于到期评分，尚未发生不是自动弃权理由；未知成本影响成本收益，未知可卖数量影响交易数量，均不自动阻止走势和集中度研究。账户建议与方向预测分别判断。固定批次按证券×期限锁定已发布方向或弃权，未发布目标可在原截止前经新判断补充。结构化行情工具按日期取行并说明默认排序，不从长 JSON 的开头猜测最近行情。
