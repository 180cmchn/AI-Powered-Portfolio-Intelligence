## 协调器审查边界

现有事件、主任务、账本流水、报告和材料列表已采用实体身份；同一实体的 `details.open` 在协调时不由服务器模板覆盖。主页面与弹窗事件分别有 surface 作用域。未变化文字不写 `nodeValue`，跨节点移动后仅在原端点仍连接且文字未变时恢复选区。表单边界保留角色专用同步、版本提示和账本预览失效逻辑。

未发现需要把所有静态结构都改为 key 或引入新前端框架的理由。未带 key 的固定布局可以按结构协调；动态实体行必须另有持久身份。新报告引用默认关闭的实现与已有新增浏览器断言一致，最新报告正文仍采用产品既有的默认展示规则，不应把“引用默认关闭”写成所有正文都默认折叠。

事件段、读取计数、报告和草稿已有容量控制；没有发现把事件正文、模型正文或供应商 Key 新写入 localStorage/sessionStorage 的代码。本次未进行辅助技术读屏器人工验收、操作系统 IME 人工输入验收或长期内存压力测试。
