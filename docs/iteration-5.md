## `reasoning_effort` 的设置与实际请求

系统设置中的控件名为“模型思考强度（reasoning_effort）”。允许且仅允许以下五个小写字符串：

`low`、`medium`、`high`、`xhigh`、`max`。

项目默认值是 `medium`，不代表上游模型的默认值。有效配置优先级为：**数据库中显式保存的值 > `REASONING_EFFORT` 环境变量 > 项目默认 `medium`**。设置 API 缺少字段时不写入默认，数据库迁移也不写入默认遮盖环境；已有合法 `high`、`xhigh`、`max` 不会被改回 `medium`。显式空串、`null`、未知字符串或其他档位会报错，不能悄悄映射。

非法环境值或直接写入数据库的非法值保留原状并显示配置错误，模型任务等待修正；基础账户和行情功能仍可使用。本轮检查没有发现需要迁移的现行旧 `thinking_effort` / `THINKING_EFFORT` 配置，因此没有为了旧提示词添加冗余兼容层。

| 配置选择示例 | Responses 请求 | Chat Completions 请求 |
| --- | --- | --- |
| `xhigh` | `"reasoning": {"effort": "xhigh"}` | `"reasoning_effort": "xhigh"` |
| `max` | `"reasoning": {"effort": "max"}` | `"reasoning_effort": "max"` |

Responses 合并已有 reasoning 设置，不覆盖必要的 mode、summary 等字段；不在顶层额外猜测多个 effort 字段。项目采用 HTTP 适配器，SDK 枚举不会把 `max` 改成其他值。思考强度独立于输出 token、温度和超时，不以这些设置替代。

模型参数拒绝会明确指出端点、协议、字段与选择值，归类为配置问题；不删参、降档、换模型或切协议重试，也不误标为原生搜索不支持。对于网关返回 HTTP 500 但明确给出参数拒绝代码的情形，同样不会按临时服务故障重复请求。相同配置下，保存报价等无关设置或服务重启不会自动重发已拒绝的模型请求；相关模型配置或认证配置变化后才自动恢复，用户仍可显式重试。

协议依据：[OpenAI reasoning 文档](https://developers.openai.com/api/docs/guides/reasoning)，核对日期 2026-10-28。该文档不构成第三方转发端点的能力证明。Chat Completions 适配保留本地函数研究，但当前实现没有该协议的原生联网适配；协议由用户选择，程序不会自动切换或另建搜索服务。

## 配置何时生效、在途任务与恢复

账户任务在后台领取时写入 `jobs.config_snapshot`；公共任务在领取时写入 `input_snapshot.config`。排队尚未开始的任务采用领取时的有效配置，已经开始的任务保持启动时配置。主 Agent、公共研究 Agent、所有子 Agent、对子 Agent 的追问、最终汇总和 HTTP 重试均继承同一份快照，没有汇总阶段降档。

每次领取记录 `model_configuration_bound` 事件，注明 attempt、前后配置摘要和绑定策略。服务中断后重新领取属于新一次执行，采用当时配置，并保留与前次的关系；旧快照未记录的历史值不补造。页面同时展示当前设置和账户/公共在途任务的旧配置，保存设置不冒充正在运行的任务已切换档位。

恢复检查账户和公共范围版本、源报价、事件、材料版本与访问权；检查点年龄上限也使用本次任务快照。有效的可见研究可以复用，恢复的汇总按新任务实际绑定配置发出，`configuration_relation` 保存旧成果与本次配置关系。旧探测成功不等于新配置已验证，不恢复或展示隐藏思维链。

独立行情刷新可以采用最新行情设置，但不改写本轮模型 effort；报告仍使用其分析快照的价格及 `data_as_of`。模型研究期间的新报价不能被直接贴成旧报告的估值时点。

## 诊断与上游支持的四个层次

| 层次 | 保存字段 | 能证明什么 |
| --- | --- | --- |
| 已配置 | `reasoning_effort` | 本轮绑定的档位。 |
| 已发送 | `reasoning_effort_path`、`reasoning_effort_sent` | HTTP 适配器实际发出的字段和值。 |
| 请求被接受 | `request_accepted`、`status_code` | HTTP 接受情况；无响应时接受状态未知。200 空结果仍使研究失败。 |
| 服务明确回报 | `reported_reasoning_effort` | 服务结构化字段报告的档位；未返回为 `null`，不从模型自述或 token 数量推测。 |

诊断还包含任务与 Agent 身份、模型、协议、端点、阶段、耗时、尝试次数及服务实际返回的用量。未返回的 token 或计费信息保持未知，不编造金额。模型调用预算限制实际 HTTP 次数，不能当成一次请求中原生搜索次数或完整费用硬上限。

能力探测绑定模型、端点、协议、effort 与认证配置指纹；设置变化后历史结果不冒充当前验证。页面刷新不发起真实探测。失败的显式函数探测会保存实际请求诊断并替换旧成功状态，避免界面继续展示过时成功。

当前真实端点的五档支持矩阵不能由本地五档测试推导。固定 Responses 版本已观察到三次 HTTP 200 空结果，不能据此宣称任何真实报告完成、原生工具成功或服务实际采用了该 effort。用户随后将 `.env` 协议改为 `chat_completions`，本轮在另一独立库重试；这是用户的显式配置改变，不是程序的静默回退。

用户修改协议后，固定旧版的公共、A、B 三任务均因缺少顶层 `choices[0].message` 失败。一次有界结构诊断发现实际回复位于 `data.choices`。旧版记录的顶层 prompt token 7,436/8,197/7,514 和 completion token 0 属于转发层，不能当成内层模型没有输出的证据。

新增兼容仅接受明确 `success=true`、`data` 为对象且符合当前协议的一层封装。标准顶层结果优先，不递归猜测、不把错误、空结果或截断文本当成功。内层 `usage`、effort 与响应 ID 按标准协议解析；外层数值用量独立记录为 `forwarder_usage`，不会混加、冒充或覆盖未知的内层计数。隐藏推理只按原有续接规则保留于会话内存，不进入诊断或报告。

## 交互、候选资料与报告修正

旧 `operation()` 在 busy 时直接返回会丢弃合法点击。现实现将操作按目标去重，读取不持有全局写锁；暂停导航响应期间的分析、重试和保存均有生产后端行为断言。提交时保存账户、输入、目标任务与 `expected_version`；迟到响应不会改投新账户或覆盖后续草稿。重复点击、受控失败和失败后的再次提交都有回归。

远端旧日志确实是等待 retry POST 响应超时；本地受控暂停复现了同一缺陷机制，但历史日志不足以证明它是该次 CI 失败的唯一原因。实际远端日志、环境差异、Linux 补充回归、最终本机冻结后复核与产物见 [浏览器回归与 CI 定位](fifth-browser-ci.md)。本地通过没有改变历史远端 `failure`。

候选事件只把公共 Agent 的明确关联判断投递到允许研究该证券的账户；当前产品使用全局候选范围，未另建复杂排除规则产品。未知关联保留待查，不默认广播。投递先可靠保存下游需求，再确认材料通知；中断重放、重复事件、候选范围变化和后续关联细化不会静默丢失或重复投递。受控 `SZ:159278` 材料证明这段逻辑，不冒充当天实际公告或利好。

原生搜索片段按 `snippet`、`excerpt`、`description` 顺序规范化：保留有效字符串与原字段，对相同文本去重，不同片段按次序合并，并记录可见长度限制。只有 URL 时仍为 `source_link`；有实际文本时为 `search_excerpt`，不会升级成“已读全文”，也不对历史空材料编造正文。

提示词要求财务条件明确指标、期间和比较基准，不直接以九个月与六个月累计金额判断改善或恶化。ETF 报告研究基金及指数，披露持仓、指数成分和权重各注实际时点；证券价格、单位净值与 IOPV 分开，无可比资料时不强算实时折溢价。没有新增事实审核关卡。

## Mac 配置、迁移与恢复

已有 `.env` 不应被样例覆盖。仅首次配置时参考 `.env.example`，其中包含：

```dotenv
MODEL_NATIVE_SEARCH=true
REASONING_EFFORT=medium
QUOTE_PROVIDER=eastmoney
QUOTE_FALLBACK_PROVIDER=sina
```

填写实际可用的模型、端点、协议及后端密钥；前端只保存密钥环境变量名。编辑 `.env` 后停止并重新启动本机服务；数据库已显式保存的设置仍优先于环境。具体安装命令及日常入口见 [README](../README.md)。

```sh
./stop.command
./start.command
.venv/bin/python scripts/manage.py status
```

SQLite schema v5 为任务增加配置快照。升级已有库前在线保存同目录 `.before-v5.bak`，保留 WAL 中已提交数据，迁移可重复执行；不清空账户、持仓、材料、建议或引用，不覆盖 `.env` 密钥。更早 schema 的已有备份步骤也保留。

需要恢复备份时先停止服务，使用 `scripts/restore.py`；它检查完整性、运行锁、模式与 schema（包含 v5），并在覆盖当前库前另存快照。不要把私有数据库或密钥加入公开提交。更详细的协议、诊断和恢复语义见 [运行时 Agent 文档](agents.md)。

隔离审计：一次独立校验导入默认应用时触发了当时为空的日常库 schema 升级，系统已自动备份；确认无运行进程、账户/任务/材料为空后，已从升级前在线备份恢复原 schema，完整性检查通过。未写入日常测试账户、未清空记录或修改凭据，自动备份保留。后续验收仅以 SQLite 只读方式加载日常设置，数据写入独立评估库。
