# 第八轮：按证券继续准备与有限补充研究

基线 `85c530c` 的问题仍存在：`forecast_tick()` 对已有 `job_id` 的批次直接 `continue`，而采集完成后又对任何已有预测的整批退出。因此第一只证券就绪后，其余暂缺或超出单轮40项的目标可能永久遗漏；另一个缺陷是任一证券就绪会把所有 waiting_data 样本同时改为 uncovered。正式方向发布的精确基准校验原本正确，本轮保留。

## 当前实现

`app/forecasts.py` 采用已有轻量 worker，新增两张小表，不增加分布式队列：

- `forecast_preparations` 按批次/证券保存未尝试、准备中、待数据、就绪、终止或过期，以及本轮开始后的尝试次数、重试时间、租约、就绪时间和原因。迁移不会推算旧请求次数。
- `forecast_research_scopes` 记录每次初始/补充/显式重试任务已分配和随后按生产上下文/工具交付的就绪证券集合。它只用于调度去重，不把入队声明成模型已研究，也不把材料收据用于内容准入。

单轮默认40项、沿用请求并发和总时限；每证券最多5次，退避60/120/240/480秒，已就绪不重复抓取。未请求目标优先，跨账户按历史尝试排序轮转，重启保留进度；并发 tick 先事务领取租约。取消清理租约，进程崩溃的租约有限到期。无可用基准不创建付费任务。真实截止和原账户版本在采集完成、入队和发布三个阶段检查；完成时过期的请求不会使方向取得发布资格。

第一只证券就绪可启动研究；已有任务 queued/running、或者已有一部分正式预测，都不停止其他未发布证券的补采。`list_forecast_targets` 返回每项准备状态、尝试、基准源/日期/价格/抓取时点/共享证据索引、是否已发布和方向资格；返回页列出实际交付证券，未返回页不声称已交付。新增基准有运行事件索引，Agent 可再次调用工具取得正文中的结构化证据；数据库更新不等于模型已读取。

初始任务完成或失败后，仅在**存在此前未分配/交付的新增就绪证券**时自动创建至多一次补充研究。仍有待补采目标时合并至少一个60秒调度间隔；没有其他等待目标可直接入队。账户已有其他在途工作时不抢占；用户取消的任务不自动重启。补充任务通过正常 Store 队列、Service、ResearchTools 和模型执行，沿用同一批次、证券/期限分母、输入版本、规则、原截止。每次实际执行继续计入原执行尝试表。后续新数据超过自动补充预算时留下“基准已补齐，但本批次自动补充研究预算已用尽；未发布”的具体原因。

发布以**证券×期限**锁定；既有方向、弃权、发布时间和引用不变。新增预测将当次使用的基准副本写入不可变 `citations.baseline_at_publication`，之后其他证券的基准补入不改变它。缺基准被拒绝的候选方向不入账；之后必须经过新的实际提交，绝不从旧报告捞取方向。用户显式重试可继续同批次未发布目标；已发布项仍被唯一约束和原记录保护。

## 日历更正与评估

根模块的日历内容修订会将既有评分安排为有界重新检查，`calendar_revalidation_pending` 立即从有效评分视图排除，历史评估保留。`evaluate_due_forecasts()` 在取得价格前重新解析已发布预测的目标日。若新解析不同或当前缺覆盖，追加 `unassessable` 日历修订，保存原目标、新解析及日历内容摘要；不静默改写原目标或按错误日期继续评分。普通价格重新抓取仍沿用原先“网络临时不可用不覆盖有效评分”的保护。已有批次的基准日被改为非交易日时，窗口显示 calendar_conflict，保留 batch_execution_status、原批次及样本；缺覆盖显示 calendar_unknown。冲突窗口单独计数，不冒充当前已确认的应运行窗口。重核本身异常不会重新展示尚未验证的旧评分。

旧测试 `test_late_baseline_does_not_rewrite_published_batch` 原先断言整个批次禁止新增基准，与本轮要求冲突；现保留并收紧保护断言为已发布证券的基准完全不变、发布记录保有原基准副本，同时要求另一未发布证券成功就绪。不是删除账本不可变断言来通过测试。

限制：自动补充最多一次，晚于该次补充才恢复的额外目标可继续取得基准，但不无限新建模型团队；保留未覆盖原因，并接受截止前用户显式重试。模型能访问新增数据不等于必然采用或给方向。真实正式窗口、实际方向和自然成熟结果另见总验收，不能由这些工程夹具代替。

## 最终冻结前的工具审查修正

只读审查在实际验收准备期间发现并用临时 Store/ResearchTools 重现两个问题：来源返回 `unavailable` 时，行查询把空结果误写成 `empty/missing` 且丢失错误；两个没有抓取时间的材料比较时，把 `None == None` 标成同一快照。第三个边界是单行或元数据超过响应预算，可能返回 `has_more=true` 但 `next_offset` 不前进。原诊断保存在 `test-results/iteration-8-market-audit.json`（记录的是修正前症状，不是当前结果）。

`app/market_materials.py` 已保留 `source_status/error`：不可达来源不宣称精确日期确实缺行，资产/基准失败分别说明；确实成功的空区间仍显示 empty/missing。快照时点缺失、无效或没有时区时为未知（null），有合法时点时说明只比较抓取时间，不宣称原子快照保证。无法装入一行的分页返回有界错误、无继续游标，并提示缩小字段或用原材料的字符分段阅读，完整已存内容不丢失。

另修正模型目标上下文：探索任务没有正式批次的基准准备过程，因此不能把缺少正式基准当作探索方向发布的硬限制。现在 `baseline_required_for_direction`、`baseline_ready`、`baseline_valid_for_direction` 分开，`direction_eligible` 与实际发布规则一致；正式方向仍由同一精确基准检查函数保护。新增真实 Service 调用链的协议替身验证探索方向能够发布，而无需伪造价格或强制弃权。
