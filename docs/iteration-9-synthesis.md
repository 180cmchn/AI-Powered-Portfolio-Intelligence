# 第九轮：计算成果在最终请求中的保留

本记录描述 2026-10-30 的本机隔离工程验证。行情、模型响应均由受控替身提供；使用生产 `ResearchRuntime`、`ResearchTools`、临时 SQLite 和捕获真实构造 HTTP 请求的 `httpx.MockTransport`。这些结果不代表真实供应商报告质量、真实方向预测或投资表现。

## 已定位的问题与实现

第八轮 `_enter_synthesis_context()` 将剩余字符预算平均分给工具输出。较长 `market_indicators` 的 `relative_return`、基准比较等字段位于逐日输入之后，JSON 前缀可能保留来源和部分行而丢失关键值。最终阶段只有 `finish_analysis`，旧提示中的回读机会实际上已经消失。另有两个相关断点：`calculate` 的检查点只保存最近 32 条；`market_indicators` 没有进入该计算检查点。

第九轮在 `app/calculation_context.py` 对真实工具输出作确定性字段投影；不新增模型审核、不按涨跌方向筛选。指标摘要保留结果、证券、实际/请求区间、样本数、方法、单位、复权/间隔、材料版本及基准版本、缺口。`calculate` 保留操作、结果和输入数量；其证券、区间、材料版本原本未提供时明确保持未知，不推测关联。每次执行有独立计算 ID，失败与后续成功共存，同来源不同区间/基准/窗口不合并。

`app/agents.py` 将完整参数和原始输出保存在会话的专用可见数据档案，摘要给出本会话可用的 `recall_context` 记录 ID。原始输入随汇总检查点持久保存，恢复时重新建立当前会话档案引用，同时保留原任务、账户输入版本、作者、轮次和模型身份。模型上下文只携带紧凑投影，不重放完整输入。没有复算或重新联网。

摘要在原有 `max_context_chars` 内先于普通长文本摘录分配空间。摘要要么完整保留，要么进入明确的索引/遗漏列表；不会截断数值字符串或 JSON 前缀冒充完整计算。研究或显式 `prepare_synthesis` 后仍有权限时可实际回读；强制最终阶段明确写明不能再调用 `recall_context`。较小预算或极多成果仍可能有遗漏，此时给出数量和身份，不承诺无界容纳。

子角色的计算在其会话内保留，完成报告携带运行时生成的计算 ID；主会话收到已完成报告的成果时建立本地档案引用，保留原作者。未完成且未交付的子研究不会仅因计算已经执行就作为主会话成果。迟到报告仍只使用现有的一次最终更新预算。

每次带计算的模型请求产生 `calculation_context_coverage`；受限最终请求产生 `final_calculation_coverage`。记录只含请求序号、计算 ID、工具、原任务/作者、状态、摘要/索引/遗漏状态和可见档案 ID，不含完整输入、隐藏推理或 Key。最终结果中的 `calculation_coverage` 可对照最后请求。其含义是已构造请求中的可见性，不等于模型实际采用，更不等于结论正确。

## 回归证据

新增 `tests/test_ninth_calculation_context.py` 共 9 项参数化用例：

- 默认 240,000 字符预算，1 条正对照和 40 条约 5–6 KB 的生产指标结果；Responses 与 Chat Completions 两种协议均捕获最终 HTTP。40 条场景先发生普通归档，最后请求逐项对照收益、相对收益、基准收益、窗口、样本、方法、复权和材料版本，全部保留；未提高调用上限。
- 40 条大输入 `calculate` 加 1 条失败、1 条后续成功，全部进入检查点。恢复请求保留 42 条摘要，原始 1,000 项有序输入可分段完整取回；不重算，失败与成功分别可见。
- 同来源不同日期区间/均线窗口，显式 `prepare_synthesis` 后从实际返回的索引调用 `recall_context`，下一次 HTTP 中收到对应完整输入。最终没有合并窗口或基准。
- 10,000 字符预算：记录哪些摘要未纳入，最终只允许提交时明确禁止回读，不将档案索引称为已读值。
- 两个子角色并发计算至共享预算收尾：两个作者的已交付成果进入主会话最终 HTTP，子报告保留计算 ID，总调用不超过原预算。
- 子计算报告在主请求期间迟到：第一次主请求没有它，唯一一次最终更新实际收到它；不扩展研究或追加无限更新。

同时执行原有上下文、主从交付、预算、迟到报告、恢复、终止工具及 SSE 回归：

## 报告表述与证据边界

第八轮真实 A 报告已取得相对收益/均线结果却在最终文本称未取得的原记录保持不变；工程复现证明了信息投影缺陷，不能证明该报告所有遗漏均由此导致。新上下文明确区分“工具已取得”“进入当前请求”“最终采用”，不会自动改写模型观点。新版本是否在真实报告中采用这些值，应以重新冻结的新验证进程和实际请求覆盖记录核对，不能从本文件推导。

`manager.txt` 与 `portfolio_researcher.txt` 补充买入规模说明：现金 20,000 元、无持仓不能推导任何买入都近乎满仓；集中度需依据明确投入额/比例或标明假设的情景，并计算剩余现金。原有成本、可卖份额不自动阻止方向研究的要求保留。这是任务说明校正，不是观点审核、方向强制或固定评分系统。旧报告不改写，用户自定义角色提示词不应被迁移覆盖。

本记录未执行真实付费模型验收，不声称新版本已改善真实报告结论。小上下文预算的遗漏仍有明确边界；历史 `calculate` 没有保存的证券/区间/材料版本仍未知。第九轮整体启动、配置、预测归属和行情重试结果见本轮主验收记录。
