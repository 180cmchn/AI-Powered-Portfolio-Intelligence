工程回归通过、源码冻结后，可在本仓库运行一次（该命令可能产生供应商费用）：

```bash
.venv/bin/python scripts/verify_twelfth_live.py \
  --run-real \
  --source data/live.sqlite3 \
  --reference-account '<已有授权配置的账户 ID>' \
  --output data/evaluations/twelfth-live-<唯一批次名>
```

`--run-real`、参考账户和全新输出路径均必须显式给出；输出限定在本仓库 `data/evaluations` 下。不要为获取成功记录重复运行。脚本最终返回 0 才表示这一轮机械验收条件满足；返回 2 表示配置、网络、执行或最终有效状态未满足，并保留所有已发生记录。入口参数错误会在实际执行前退出。

脚本复用第十一轮 `configure()`：以 SQLite `mode=ro` 读取参考账户的有效角色覆盖、供应商/连接/发现目录及安全凭据引用，复制到隔离库；额外保留供应商凭据撤销标记。模型、协议、五档 effort、模型请求和整轮预算不降级。只按项目已有引用解析凭据，不访问其他应用凭据、不运行能力探测、不保存 Key。配置不满足时明确失败。

准备进程 `worker=False`，使用实际 FastAPI 证券识别、账户、交易预览和确认入口创建 100000 元虚拟账户；三组输入沿用第十一轮：518880 的 100 份 × 10.000、002354 的 1000 股 × 10.00、159599 的 1000 份 × 2.500。价格数量明确为虚拟算术输入，不冒充行情或实际券商成交。核对每笔预览与回执、最终现金 `86484.90` 和持仓数量后，检查准备期模型 attempts 为 0，且只有最新任务可运行，才释放它一次。

真实阶段启动新的隔离 worker 进程，使用生产任务执行、发布、调度 tick、建议检查与需求派发。隔离设置暂停周期研究、市场定时刷新、预测定时评分和新闻扫描，避免验收外的周期付费；模型任务按已有配置正常访问授权网络路线。建议观察仍经过正常 worker tick，不 mock 时钟、不伪造旧报价、不重写报告状态。主任务不成功时停止，不增加卖出第二轮、不重试业务。原配置内部有限 transport retry 仍按冻结策略执行并逐条记录。

有完整报告后观察至少 10 个相隔 1.1 秒的正常轮询；干净停止该进程，用同一最终代码和隔离数据库启动另一新进程，再观察 10 轮。检查每轮与最终落盘的 report_id/status；历史曾发布但最终 stale 不会记成当前有效。报告自然带来 stale 价格条件时单列记录；报告没有相应条件则写明此次真实运行未覆盖首次旧报价场景，受控回归证据不混入真实成功。

如果生产机制产生额外自动任务，完整保存其来源、状态、attempts 和请求，然后结束这次单轮验收并返回 2；不会删掉不利记录，也不会继续加人工研究。退出时只终止该脚本拥有的隔离进程；在途取消和未知费用保留。不会操作日常 8765。端口由父进程预留随机 socket 并传给子进程，重启后地址可能变化，终端每次会输出真实 URL 和账户 ID，可供运行期间实际页面阅读检查。
