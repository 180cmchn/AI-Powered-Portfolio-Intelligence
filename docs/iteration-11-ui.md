# 第十一轮界面验证

## 修复与范围

- `app/static/app.js` 的角色页面采用局部 DOM 协调：轮询仍刷新账户、任务、事件与配置，但原角色表单和文本框保持连接，不再因后台状态变化移除后重新插入，也不在焦点仍有效时调用 `focus/setSelectionRange`。离开页面再返回时仍按稳定键保留未保存输入及内部滚动；普通表单的恢复顺序为焦点/选区之后恢复 `scrollTop/scrollLeft`。
- `app/static/sixth.js` 全局编辑键为 `role-global-{role_id}`，账户模型为 `role-{account_id}-{role_id}`；每个编辑 `details` 另有稳定键。角色服务器版本改变时保留本地内容并显示提示；原版本保存经后端 CAS 校验，409 保留草稿。用户可明确重新载入已保存值；成功保存与明确重新载入才替换表单。
- 密码输入沿用当前页 DOM 生命周期，不进入草稿 map、sessionStorage 或日志。角色切换期间先显示当前目标的读取状态，避免把上一账户覆盖值短暂显示为新账户值。
- 完整 `.task-status-card` 仅在 `overview` 的页面标题之后显示。其他九个页面没有同类大卡；提交中/结果未知用短提示，已接受回执 toast 提供“查看任务”入口，详情不偷偷改变 hash。`completed` 等终态优先于遗留的 `stage=synthesis`。
- `app/static/ledger.js` 是持仓页面默认入口：买入/卖出、后端精确预览、用户确认成交价、交易流水、资金调整、独立股票/ETF佣金与最低收费、末笔实际费用更正和末笔撤销。价格/金额提交为十进制字符串，不由 JavaScript 浮点生成账务事实。预览后输入改变即失效，保存时再核对账户和费用版本。
- 原快照编辑保留在“高级：导入期初 / 快照校正（不是买卖）”折叠区，要求原因，可明确补充有依据的期初可卖量。名称/偏好使用独立元信息 PATCH，并保留第十轮 operation ID 回执核对。
- 设置页同时展示首有效事件、无有效进展、普通请求硬上限、最终/恢复汇总硬上限、子任务和账户整轮预算。旧值只作迁移说明，不再作为新语义字段提交；不合理的预算关系给出可见说明。

## 验证方式

`tests/frontend_eleventh.mjs` 启动 `tests/eleventh_browser_server.py` 的生产 FastAPI、真实静态模块及临时 SQLite，并绑定随机本地端口。worker 关闭；证券目录、已保存报告和后台事件为明确测试夹具，不调用实际供应商，不接触日常数据库。

同一临时生产应用分别加载 Git 基线 `874b987` 的原始 app.js/sixth.js/style.css 与最终静态模块。基线对照不是复制 `rememberDrafts` 的独立玩具实现。使用真实鼠标 wheel；比较 DOM 身份、文本框纵/横向滚动、选区起止及方向、focus、details、页面滚动和文本内容。固定版每种场景连续触发至少两个 4 秒轮询周期。

IME 用浏览器 compositionstart/compositionend 事件检查节点不被断开、不额外触发 compositionend；这是生产 DOM 生命周期回归，并非操作系统中文输入法的人工验收。

最终详细证据在 `docs/eleventh/ui-browser-evidence.json`（原始输出 `test-results/eleventh/browser-evidence.json`），界面截图在 `docs/eleventh/ui-trade-ledger.png`。这些不包含 Key 或模型隐藏推理。

- `PYTHON=.venv/bin/python node tests/frontend_tenth.mjs`：通过，保留证券解析、回执幂等、对话框滚动/焦点、任务来源/重试/恢复/报告版本；按新业务要求将旧快照写入场景改为显式有原因的校正，将大卡断言限制到总览。
- `PYTHON=.venv/bin/python node tests/frontend_eleventh.mjs`：完整生产矩阵通过，最终逐项数值见上述 JSON。基线三个场景均为 scrollTop 1200 → 0；修复后每个场景两次轮询均为 1200 → 1200 → 1200，内部横向滚动、选区方向与文本、焦点、details、页面滚动和 DOM 身份保持。

## 独立模拟账本的界面可复算结果

这些价格/数量是受控浏览器输入，不代表用户真实交易或当前行情：初始现金 100000，依次买入 002354 的 1000 股 × 10、159599 的 1000 份 × 2.500、518880 的 1000 份 × 7.000，后端余额依次为 89994.90、87489.90、80484.90。518880 同一模拟交易日全卖 1000 份 × 7.200 后为 87679.90；按有依据费用更正将最后卖出佣金从 5.00 改为 2.50 后为 87682.40；转入外部资金 1000 后为 88682.40，已实现盈亏仍为 192.50，未将转入当作收益。

第三笔买入刻意在服务端提交后丢失响应，页面使用原 operation ID 查回执：只发生一次交易 POST，现金和持仓不重复更新。双击提交被合并。另一账户现金与账本保持原值。原始费用与成交记录在费用更正后仍完全相同，新增费用调整引用原单。

视觉检查补充验证：交易持仓从已核对证券目录显示名称及股/份单位；002354 为股，159599 为份。费用更正明确显示“费用调整”，不误标为另一笔卖出。最终截图等待短回执提示自动消退后拍摄，避免遮挡表单。

## 最终只读功能复核：已支持与界面边界

此节为源码只读复核，不是额外一轮浏览器或实际模型测试；复核过程中没有修改源码，也没有再次运行全套测试。范围为 `app/static/app.js`、`sixth.js`、`ledger.js` 及其现有 API 约定。

| 要求 | 当前界面实际支持 | 边界与操作方式 |
| --- | --- | --- |
| 数量与证券身份 | 买卖方向、六位/带市场代码、整数股/份、手动单价；持有量和当前可卖量分开；当前持仓名称/单位来自已核对目录 | 浏览器只做必填/整数输入提示，整手、零股、T+1/T+0、超卖与资金检查由后端决定。未知期初可卖量不会猜日期，需要高级校正明确填写。全部卖出后账本仍可能显示数量 0 的历史头寸；该头寸若不再属于当前 metrics，名称/单位可能只显示代码及“待确认”，历史成交身份仍保存在流水中。 |
