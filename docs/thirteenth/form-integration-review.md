# 校正表单集成审查

`tests/frontend_thirteenth_correction.mjs` 通过真实 HTTP 记账产生 3010.03 / 300 的循环小数单位成本，再操作实际高级校正页面。对照原始请求、预览、FormData 与库中完整 position/lots，现金校正发送稀疏 holdings，另一证券校正和显式未知成本均保持未改证券的精确事实。

独立审查同时检查了字段命名、明确未知 checkbox 的选择器、行删除/新增、输入与版本失效、路由切换及保存过程中继续编辑。校正表单的 symbol/quantity/cost/available 输入按原始行基线构造 patch；明确 checkbox 生成 null，空白保持原值，行移除发送 remove:true。零数量编辑与移出持仓范围分别处理，历史账本保留。提交再次核对 FormData 签名和输入版本，生产后端仍核对预览 token 与 CAS。

补充修复：证券识别的“选择匹配项”此前程序修改 value 却只标 dirty，未发 input；现发真实 input 事件，使校正预览立即失效。原提交签名已能阻止错误落账，此修复同时保证按钮与当前输入一致。

新成本 / 可卖量 checkbox 增加了 field wrapper，旧布局只对直接 `.field` 子元素生效。补充只作用于 `#account-form` 的子网格，将四个值、帮助文字与未知选项按列对齐；窄屏转为逐字段纵向布局。对 1360 / 800 / 390px 均断言页面无水平溢出、输入不重叠、不出视口且宽度至少 80px；实际查看了 [桌面截图](correction-layout-1360.png) 与 [390px 截图](correction-layout-390.png)，字段及勾选项可读。800px 见 [截图](correction-layout-800.png)。长精度值保留在输入框中横向读取，不以显示舍入反写账本。

延迟回执测试先保存现金 98000.00，在响应被截留期间输入 99000 并修改原因；落库仍为本次已提交的 98000.00，界面保留新的未提交草稿且确认按钮禁用。再次预览明确显示 98000.00 → 99000.00，重新确认后重载干净基线。跨研究页返回持仓页仍使用同一个草稿 DOM；离页期间资金流水改变版本会使旧预览失效。

结果见 [correction-browser.txt](correction-browser.txt)、[完整请求/精确状态/布局测量](correction-evidence.json)。追加测试第一轮仅因期望现金字符串写成 98000 而生产规范结果为 98000.00 失败；更正精确格式断言后完整通过，没有删断言或增加 sleep。本测试无模型调用；没有操作用户账户或日常实例。
