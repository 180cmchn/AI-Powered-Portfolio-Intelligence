# 正常 A 失败后的本地修复

正常 A 的第十次请求仍在接收有效流事件时触及本地 300 秒请求硬限。该次取消来源已明确，但不能据此反推早先所有 `client_gone` 的原因，也不能将尚未取得的 A 报告记作成功。原始请求、账本、停止锁及 10/16 次计数保持不变，见 [实际证据](business-a-live-evidence.json)。

本次后续审计发现了两个可直接修复的本地缺陷。

## 恢复时缺少已经交付的财务工具内容

原代码在 ModelClient 将有界工具结果放入会话后保存了交付回执及内容哈希，但未保存这段可见内容。Runtime 保存的材料清单又主要来自原生搜索索引、显式保存及计算引用，因此部分直接 `fundamentals` 返回不在检查点的材料版本保护中。恢复新会话时，工具返回的证券、期间、单位和数值会丢失，裸算式不能替代这些语境。

真实 A 的旧检查点包含 51 个材料 ID；三份已交付财务材料未进入其版本保护。只读核对确认原记录仍是 `synthesis_ready`，且未保存对应可见正文；这个历史状态不证明材料保护完整。新代码诊断为 `manager_material_guard_incomplete`，不会补写旧正文或版本证明；此外该检查点已经超过原 1800 秒时效。见 [只读核对](post-a-old-checkpoint-audit.json)。

新交付回执保存主 Agent 实际收到的有界结果与哈希，直接材料同时进入检查点索引和版本保护。恢复只重新归档这段已保存内容，并经既有上下文投影提供正文或新会话内的取回指针。不会从完整材料库、旧大工具档案或未报告子研究中补出更多“已读内容”。旧回执没有正文时不注入正文；仅来源链接仍是索引；部分读取仍保留范围。追加研究再次中断时，保存比较也包含合法恢复的旧回执，避免已有检查点挡住本次新增材料的保存。新版本、更正未处理、权限、账户、行情、时效及恢复次数检查均继续执行。

受控回归通过实际 API、Service、Runtime 和 ModelClient：交付财务行后制造流失败，显式重试，再核对实际发出的模型输入或取回内容。红灯和最终结果分别保留；这属于工程验证，不是新的供应商成功记录。新增 17 项用例及相关恢复回归共 134 项通过，见 [定向验证](../../test-results/fifteenth/checkpoint-materials-validation.json)；只有主生产夹具贯穿完整 API 链，其余边界在对应 Store/Runtime 层验证。

## 超过 100 条研究记录会静默截断

原最终预检未检查 `research_records` 数量，持久化却使用 `records[:100]`。现在预检与持久化共用同一数量和结构规则，生产完整 `finish_analysis` schema 明示 `maxItems: 100`。第 101 条在 accepted 之前返回字段路径 `research_records[100]`，同一主 Agent 可使用既有一次纠正预算重新提交。程序不替模型删除观点，旧记录保持可读。

实际 ModelClient→Runtime→Service→SQLite/API 夹具验证 1、100 条全部保存，以及 101→100 的一次纠正；重复发布与恢复不重复追加。单独持久化超量也明确拒绝，原数据不变。新增用例先复现两处失败后转绿，相关 152 项通过，见 [交付审计](delivery-requirements-audit.json)。

这些修改没有放宽请求、空闲、整轮或正式预测期限，没有改变日常供应商、模型矩阵、代理、证书、凭据或账本。当前 Mac 升级说明已修正为 schema 11 / API contract 13；无需重建数据库。真实 A 后续执行及其他业务阶段仍须分别满足原任务授权和验收条件。


## 后续业务阶段的离线路径

现有业务验证器已支持 `a_initial → a_after_sell → b_cash`。A 选择卖出 100 份 T+0 黄金，通过实际预览/提交 API 验证版本 4→5、现金 87479.90、累计费用 20.10；B 是独立 100000 元现金账户，159278 被锁入实际任务范围。夹具进入 Service、Runtime、ModelClient 和事务发布，并检查发布后/重新创建服务后状态。B 读取共享公共原料，A 私有材料仍不可读，A 报告也不作为 B 的既有结论。

每阶段只读绑定前一阶段的实际发表正文、独立内容复核和数据库身份，另设授权与 HTTP 额度，未知结果即停。卖出与买入是二选一，本路径没有实现另一个买入分支。相关 business34、recovery16、context50 共 100 项通过，见 [定向结果](../../test-results/fifteenth/business-matrix-targeted.txt)。这些都是受控夹具；真实 A 尚未发表，因此真实后续 A 卖出和 B 阶段仍未启动，也未获授权。


最新统一冻结为 `247c5ba48205bd2bffa2dd3419585056cdd6ea808d6e753d827d09a9bd1e3f44`。Mac 与 Linux/Python 3.12 全套各 **1367 项通过**，各保留 1 条既有依赖警告；十一组浏览器全部通过，三者直接对应同一源码。见 [本次整套验证](post-a-regression.json)。本轮后续工程没有新增付费模型请求，这份工程记录完成时原 A 为 10/16 次；随后实际重试结果见最新状态。

## 单次恢复实际遇到行情变化

**最新恢复结果：11 月 3 日 00:28 的单次恢复已获授权，但在发送前停止，实际模型 HTTP 为 0。** 正常行情刷新因东财连接错误转到新浪，三证券来源与数据时间改变，检查点的 research_inputs_changed 校验阻止继续汇总。无报告、无额外模型扣次；A 仍为 **15/16**、余 **1 次保留**。此后检查点于 00:31:40 按原期限到期，授权仅限有效期内，未清除停止锁或再次执行。本次零请求失败不能解释前次 290 秒模型断流，也不宣称修复了该传输问题。

离线恢复夹具曾固定行情不变；新回归必须让实际 Service 刷新来源和数据时间，证明任何降级为重新研究的路径都在模型 HTTP 前拒绝。只改隔离验证器的诊断和测试，不删除生产行情刷新，也不放宽材料、价格、版本或 TTL 校验。详见 [真实执行证据](business-a-single-recovery-live-evidence.json)。
